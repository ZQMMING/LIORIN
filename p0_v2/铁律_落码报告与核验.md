# 铁律：落码报告与核验（2k / 2l）

2026-10-06 立。来源：格局病域"三条件门控从未落码"事故（b6b1276 裁落 → 27fb30b 只落求值器主体，门控静默搁置，后续报告未标"未落"；与 dm_wx NameError 同类）。

## 新规 2k：裁定落码 → 同轮报告必须含三件

任何"用户裁定落码 X"的执行轮，报告必须逐条含：

1. **落码清单**：每条 `文件:行 / 改动内容`（如 `engines/common/ge_jie_layer.py:1119 evaluate_po_ge 加门控`）；
2. **git log -S 证据**：证明改动在提交里（`git log -S "<符号>" -- <文件>` 命中）；
3. **未落项显式列出**：若有未落项，附原因（如"门控需先核原文，本轮只落求值器主体"）。

缺任何一件 = **报告无效**，裁定视为未落。

## 新规 2l：报告"已落"前必须核代码

- 报告"X 已落码/已实现"前，必须 `git log -S` 或读源码确认改动真实存在；
- **不核就报"已落" = 违规**（与"核验读源码不读注释"同级）；
- 提交信息自述（"加了门控""实现了 X"）不构成证据，提交信息本身也要被 `git log -S` 核。

## 事故复盘（为什么立这条）

- b6b1276 裁"evaluate 加三条件门控出成品事件"；
- 27fb30b 提交信息自述求值器主体，未提门控；后续报告未标"门控未落"；
- 到 3857c2a7 才用 `git log -S "evaluate_po_ge"` 查出：门控从未实现，仅 27fb30b 一处提交。
- 根因：**"报告说落"与"代码实落"之间没有强制核验环节**。

## 执行口径

- 每轮落码报告按 2k 三件输出；
- 引 git 证据用 `git log -S <符号> -- <文件>`（符号须是改动中唯一性强的标识符）；
- 未落项不隐藏，标 PENDING + 原因 + 触发条件（等什么）。
