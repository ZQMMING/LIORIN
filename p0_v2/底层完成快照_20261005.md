## 六、立规清单（工作规范，已进 `shuntian-slice-audit` 技能）

```
1. 独立进程验证，禁持久 kernel
   —— 持久 kernel 复用旧模块，产生静默假数据（本轮曾连续三轮报「10 键」，实为 18 键）

2b. 判「字段是否被消费」= 落码时【声明】，不靠审计猜
   COMPUTED / META_FIELD / PENDING；未声明类型的字段不得进契约

2c. 元规（上位规）：分类/统计优先用【结构标识】
   —— ID 前缀 / 字段类型 / 枚举值 / AST 节点类型；
      文本模式（关键词/正则）只作辅助，不作最终判据

2d. 「全 0」是一等信号，先怀疑扫描器
   —— 凡「全部 0 / 全部相同」，先跑探针验证扫描器本身

2e. 脚本写完必先过【已知答案的样例】，再跑真实数据

2f. ★ 检查点（比规更硬）：报数前必报「探针名 | 预期 | 实测 | 通过?」
   探针不 PASS → 该脚本的任何数不许进下一轮
   未报探针的结果 = 默认不可信，撤回重跑

2g. 候选池必须声明下游用途
   机器判→高精度宁漏勿错 / 人工核→宽召回宁错勿漏 / 线索池→只要覆盖

2h. 报数前先确认「我跑的是哪个文件」（路径 + 字节数 + 时间戳）
   工具写入失败时可能跑的是旧版 —— 本轮侥幸对了，用的是新文件名

2i. ★ 字符集作结构标识时，先核该字符在本语境的【角色】
   ——「己」在「己未宮」是天干，不是支名。修法：按句式定位，不按字符

2j. 换新结构标识，要过【全样例验证】——差一个也 FAIL
   —— 修 A 错时用的新标识，可能只覆盖 A 的样例，不是全集
```
