## 〇、这份流程要解决什么

v1.8 §10 写了 5 条前置约束，但**约束是「应当」，不是「必须」**。

2026-09-30 我在写完 v1.8 §10 后不到一小时，就违反了其中的约束 1。说明**规范写了 ≠ 执行到位**，缺的是执行层的强制卡点。

本流程把 5 条约束从「应当」变成「必须」的流程卡点。

---

## 一、核心原则：探针 bug 优先假设

**报出异常时，先假设探针有 bug，再假设内容有问题。**

### 1.1 三次连错的实际顺序

| # | 我的第一反应 | 真相 | 应有顺序 |
|---|---|---|---|
| 1 | `XI_JI.011` 是伪句/编造 | 原文真实，**四源一致** | 先查探针 |
| 2 | 底本漏了那一句 | 底本**完整**含该句 | 先查探针 |
| 3 | 探针失败 → 结论不可信 | 探针 bug：**`**原注**`+`……` 导致首块失配** | 先查探针 |

**三次都先假设「内容有问题」，三次都是探针问题。顺序反了。**

### 1.2 为什么必须是这个顺序

探针是**工具**，内容是**对象**。工具出错的概率远高于对象出错——
尤其在古籍场景：异体字、全半角、注疏标签、省略号折叠、跨段拼接，任一项都能让正确内容失配。

而如果先假设内容有问题，代价是**误删或误标正确切片**，且这种错误不会报错——它看起来像是正常的审计结论。

## 二、强制双验证卡点（探针未命中时）

**脚本判「原文在底本中未命中」时，必须完成以下两步验证，才可下「内容有误」结论。**

```
探针报「未命中」
  ↓
【卡点 1】查外部权威版本
  │   维基文库 / ctext 中国哲学书电子化计划 / 古文岛 / 其他可查底本
  │   找到 → 该句流传广 → 回底本复核（卡点 2）
  │   未找到 → 进入卡点 2
  ↓
【卡点 2】回锁定底本人工核对
  │   不是「用脚本再搜一遍」，是**人工打开底本、逐字比对**
  │   底本中在 → **探针 bug**，修探针，不动内容
  │   底本中不在 → 继续卡点 3
  ↓
【卡点 3】仍判有误时，须写明三条
  │   ① 探针已按 §10.1 约束 4 统一四类边界后仍失配
  │   ② 外部权威版本亦无此句
  │   ③ 锁定底本逐字核对确认无
  ↓
方可标注「内容有误」
```

**两验证都完成前，不得下「内容有误」结论。**

## 三、AI 搜索的定位与三条边界

**AI 搜索是固定第二手段**——探针报出后必走，不由主观判断决定。

### 3.1 边界一：外部搜索只作旁证

外部搜索**不能取代锁定底本**。最终定性必须回锁定底本逐字核对。

> 依据：v1.8 §2.1 版本锁定——每本书先锁定底本。外部版本可能与锁定底本不同。

### 3.2 边界二：多源一致 ≠ 准神

四源一致只说明**这条原文流传广**，**不说明这条是准神**。

准神归属仍按 v1.8 §1.3.1 判：DTS 刘本 = `primary`，余五书 = `support`。

> 实证：`XI_JI.011` 四源一致，但那也只是「这句在多个版本里都有」，与它是否 primary 无关。它是 DTS 十八、战局章原注，才是 primary。

### 3.3 边界三：外部版本 ≠ 锁定版本

外部搜索用的版本可能与锁定底本不同。**差异登记为「版本分歧」，不强行统一。**

> 实证：`HUA_SHEN.006` 化气十段锦在锁定底本中有两处（行4920 原典二段 / 行7131 补遗十段全），字句小异。此差异已按 v1.8 §2.3 登记为版本分歧。

## 四、探针比对的四类边界统一（v1.8 §10.1 约束 4）

报出之前必须先做归一化，否则探针结果无意义：

| # | 归一化项 | 具体做法 |
|---|---|---|
| 1 | BOM | 去 `\ufeff` |
| 2 | 全半角 | 标点、字母、数字统一 |
| 3 | markdown 标记 | 去 `**`、`【原注】`、`【通考注解】`、`【益说】` 等标签 |
| 4 | 注疏标签 + 省略号 | 去 `**原注**：` 等标签前缀；`……`/`...` 必须移除后再分块 |

**分块探针的实现要求**：

- 分块长度 ≥ 20 字（过短易落在标点/标签边界）
- 块内不得跨注疏标签或省略号
- 覆盖率 = 命中块数 / 总块数

**探针报出前，先自查这四项是否已处理。未处理不得报出。**

---

## 五、DUANYU 赋文层豁免（v1.8 §10.1 约束 5）

赋文本就跨段拼接，不适用覆盖率要求。

**实证**：3 条 DUANYU 切片覆盖率仅 3%~8%，但底本行号与标注完全吻合——
- `DUANYU_WANG_SHUAI_MING_TONG_FU_002`：标注 11932-12170，实际起始行 11932
- `DUANYU_REN_SHI_WEI_JING_PIAN_001`：标注 12506-12698，实际起始行 12508
- `DUANYU_REN_SHI_YA_QUAN_ZHAI_JIN_001`：标注 12443-12504，实际起始行 12445

成因是赋文体例：**正文与逐句夹注交替连排**（`真官时遇命强…` / `此月令正官格也。` / 下一句正文），探针跨夹注边界必然失配。

**赋文层切片另行核对**：按「标注行号 vs 实际起始行」判定，不按覆盖率判定。

## 六、流程速查

```
探针报出
  │
  ├─ 探针已统一四类边界？ ──否→ 先修探针，停
  │        │是
  │   是 DUANYU 层？ ──是→ 按行号核对，不看覆盖率，结束
  │        │否
  │   覆盖率 ≥90%？ ──是→ 假阳性，归因归档，结束
  │        │否
  ├─ 卡点1：AI 查外部权威版本
  ├─ 卡点2：人工回锁定底本逐字核对
  │        ├─ 底本中有 → **探针 bug**，修探针，不动内容 ✅
  │        └─ 底本中无 → 卡点3
  └─ 卡点3：写明三条依据 → 方可判「内容有误」
```
