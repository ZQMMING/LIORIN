## 〇、一句话

**用脚本探针自动判定「MD 切片原文是否在底本中」，假阳性率高达 99.6%。探针策略不可靠，只能人工复核。**

## 一、实验设计

### 1.1 对比对象

| 脚本 | 探针策略 |
|---|---|
| `audit_md_original.py` | 首 15 字，**不清洗** |
| `audit_md_original2.py` | 清洗后取中段 `[10:25]`（15 字） |
| `audit_md_original3.py` | 清洗后取首 8 字 |

### 2.2 假阳性率

| | 报出 | 真缺口 | 假阳性 | **假阳性率** |
|---|---|---|---|---|

### 2.3 三脚本相互关系

| 指标 | 值 |
|---|---|
| 三脚本一致（1∩2∩3） | **14** |

**三个脚本彼此不一致**，交集仅 14、并集 256。它们不是「同一口径三次重复」，是**三种探针策略各报各的**。

## 三、根因分析

### 3.1 假阳性来自四类边界处理差异

| 差异点 | 说明 | 后果 |
|---|---|---|
| **标点** | 底本用 `，；：`，切片用 `,;:` 或全角/半角混用 | 探针含标点则必然失配 |
| **注疏标签** | 切片原文段混入 `**原注**`、`**注解**`、`【注】` | 探针落在标签上则失配 |
| **省略号折叠** | 切片用 `……` 把底本多句折叠成一段 | 跨折叠点的探针断裂 |
| **跨书并置** | 来源双标切片把两书原文并置（`（DTS…）（PZZQ…）`） | 探针跨越书边界必然失配 |

### 3.2 为什么不能用并集或交集

```
交集 14  → 三策略都判有问题的，是真问题的高置信区，但覆盖率极低（漏 99% 真问题）
并集 256 → 任一策略判有问题的，假阳性 255 条（99.6%）
```

**结论：并集与交集都不可用，只能人工复核。**

### 3.3 唯一真缺口

`DUANYU_XUAN_JI_FU_001.md`（SFTK 玄机赋，737 字，底本最长命中 8%）。

**注意**：该条是 DUANYU 赋文层，赋文本就跨段拼接，覆盖率低**可能属正常**，尚未判定为「切错段」。

## 四、对 v1.6 §10 校对流程的补充建议

现行 §10 流程：

```
AI捞候选 → 人工粗筛 → 原著核对 → 字符层检查 → 语义层检查
→ 准神归属检验 → 分型检验 → 进MD文库
```

**建议在「字符层检查」前增加一道，并明确其能力边界：**

```
AI捞候选
  ↓
人工粗筛
  ↓
原著核对                        ← 人工，不可跳过
  ↓
字符层检查（字是不是这个字）      ← 人工核对 OCR/异体
  ↓
★ 底本可定位性检查              ← 脚本可初筛，但结果仅供人工参考
  │   ⚠️ 脚本假阳性率 ~99.6%，不得据此直接判定「原文有误」
  │   ⚠️ 也不得用多个探针策略的并集/交集作为判据
  ↓
语义层检查（是不是这个意思）      ← 人工
  ↓
准神归属检验
  ↓
分型检验
  ↓
进MD文库
```

### 4.1 可写进规范的硬性约束

| # | 约束 |
|---|---|
| 1 | 脚本可做「原文是否可在底本中定位」的**初筛**，**不得**据其结论直接判定切片有误 |
| 2 | **禁止**用多个探针策略的并集或交集作为判据（假阳性 99.6% / 覆盖率极低） |
| 3 | 报「未命中」的切片**必须人工复核**后才定性 |
| 4 | 探针比对前须统一：去 BOM、去全角/半角差异、去 markdown 标记、去注疏标签 |
| 5 | DUANYU 赋文层切片豁免覆盖率要求（赋文本跨段拼接），单独核对 |

## 六、已修正的审查器 bug（本实证促成的复核）

对比过程中顺带发现 `audit_md_reverse.py` 三个判定 bug，均已修正：

| # | bug | 现象 | 修正 |
|---|---|---|---|
| 1 | 「(注：)」无条件报警 | R2 报 44 条，实为「不混用任铁樵阐微」等**反向声明** | 改为「底本中查无此注」才报；R2 → **0** |
| 2 | 来源只认中文书名 | 不认 `DTS`/`PZZQ` 等缩写，99 条无法定位 | 补缩写识别；R1 未定位 246 → 165 |
| 3 | **来源含「参校/兼校」时归错书** | `DUANYU_XUAN_JI_FU_001` 主源是 YHZP（完整），但因「参校 神峰通考」被归 SFTK，去 SFTK 找 YHZP 全文 → 「覆盖率 8%」假信号 | 只取来源第一段（主源）并剔除次要来源标记 |
| 4 | 元数据目录未排除 | `00_元数据/` 下规范文档被当切片扫描（探针实证文档自身报 R2） | 排除 `00_元数据/` 与 `_` 前缀文件 |

**bug 3 的处置结论**：修正归书后确认该切片 **100% 完整**——实际 YHZP 行 7516-7534，与切片标注「YHZP行7516-7534」完全吻合，737 字连续（25 块中 24 块连续，1 处断裂为赋文换行差异）。**对应本文件 §3.1 所列三种口径之第二种：切片完整，是玄机赋的某一段。**

> **这正是本实证的价值**：假阳性率 99.6% 意味着，任何自动「未命中」结论都必须人工复核，否则会把一条完全正确的切片误判为「切错段」并触发无谓的重切。
