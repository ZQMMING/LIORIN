> 建档：2026-09-30

---

## 一、这是什么

**案例 = 理论演示实例，用于矫正引擎。不是标准答案库。**

依据《案例引擎调试方案》v1.0：

| 定位 | 说明 |
|---|---|
| 案例 = 理论演示实例 | 不是标准答案库 |
| 断语 = 演示用语 | 不是最终判决 |
| 用分歧率**诊断**引擎缺哪个模块 | 不是评判引擎对错 |
| 目标：每层理论模块建全 | 不是追求分歧率归零 |

## 二、与切片层的根本区别（最重要）

| | 切片层（MD文库） | 案例层（本目录） |
|---|---|---|
| 底本 | **DTS 京图撰+刘基原注本**（唯一定本） | 可用任铁樵注、徐乐吾评注、后人增补 |
| 依据 | v1.6 §2.1 版本锁定 | 《案例引擎调试方案》§3.3 案例权威性分级 |
| 允许注疏？ | **否**。§2.1 明文「不用任铁樵《滴天髓阐微》」 | **是**。任注、徐注均为旁证级 |
| 用途 | 引擎规则的 canonical 依据 | 校正引擎、验证规则 |
| 对标口径 | 不参与对标 | 按书分层对标（铁律一：不跨书混调） |

**所以：案例层命中率低、含增补，是正常状态，不是缺陷。两者不该对齐。**

## 五、legacy 目录：`legacy/`

**保留理由（2026-09-30 裁决）**

`legacy/` 下是**旧案例审计链**的构建脚本，保留作**证据链**，不参与当前 MD 链路。

**为什么必须保留：**

1. **它是「案例允许增补」这条规则的判定现场。** `PZZQ_audit_report.md` 第 4 关识别出 306 条徐乐吾增补命例（邵力子、孔祥熙、谭延闿、宣统、光绪等民国人物），并逐条写入 `pollution` 字段——这段判定过程只有这批脚本能重现。删了，以后再遇版本污染就没有判定依据。

2. **准神规则的证据链要求。** v1.6 §1.3.1：「物理删除与静默否决均不采用——被刘本否决的切片仍须入库并显式标注，保证证据链可追溯与可回归。」旧脚本同理。

3. **归档可逆。** 万一将来发现某个旧脚本有独特检查逻辑，可从 `legacy/` 捞回。

**如何避免误用：**

- 所有 legacy 脚本头部已加 `# LEGACY:` 注释
- **legacy 脚本的产出物（`*_audit_report.md`、`*_classification.json`）是案例层历史结论，与 MD 切片层的当前结论互不矛盾**——两者针对不同对象
- 跑当前链路时不要调用 `legacy/` 下的脚本
