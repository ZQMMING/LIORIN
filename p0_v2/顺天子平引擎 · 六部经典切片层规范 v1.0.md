## 一、核心原则

### 1.1 为什么先 MD 后 jsonl

- **错误**：原文 → 脚本直接切 jsonl → 反复改
- **问题**：改 jsonl 看不见原文上下文，校对困难
- **正确**：原文 → AI 捞候选 → 人工粗筛 → 原著核对 → MD 切片 → 全部校对合格 → 再批量转 jsonl

### 1.2 切片铁律（八条）

1. **原文优先**
2. **版本锁定**
3. **宁漏勿错**
4. **分型检验**
5. **字符≠语义**
6. **不脑补**
7. **准神归位**
8. **病药分域** —— 切片时先判「这条属于哪个病域」

## 二、准神规则（最高裁决规则）

以《滴天髓》京图撰、刘基原注本（以下简称刘本）为**唯一准神**。余五书是取材池，不是裁判。

### 2.1 五条规则

| 规则 | 内容 | 效力 |
|---|---|---|
| 准神唯一 | 凡旺衰、格局、从格、调候、病药、用神之义理之争，以刘本原文为最终裁决依据 | 最高 |
| 余书降位 | 余五书与刘本相左一律以刘本为准；其"主/重点"标注统一视为"旁参" | 强制 |
| 教义归位 | 某主张属哪部经典即挂哪部名下 | 强制 |
| 旁参不废 | 余书内容照切、照入库、照作旁证 | 强制 |
| 规则不适用面 | 刘本未涉及的工程操作性事项不适用 | 除外 |

### 2.2 操作要求

- 每条切片"出处"字段只写原文确实出自的那部经典
- 入库前先问：**这句话到底是刘本说的，还是余书说的？**
- **注疏标签的归属按准神规则判，不按字面判**

| 注疏类型 | 归属 | authority |
|---|---|---|
| 刘基原注（DTS 刘本内） | 归 DTS 刘本 | `primary` |
| 张楠原著内含的"通考注解" | 归 SFTK，余书身份 | `support` |
| 后人注解 / 徐乐吾评注 | 归 `LATER_COMMENTARY` | `support` |
| 无法判定 | 标"存疑" | `待核` |

### 2.3 准神规则执行落地

**两层都执行，各司其职。切片层负责"标注与降权"，推理层负责"最终裁决"。**

#### 切片层

每条切片头部强制填 **准神归属** 字段，取值 **准 / 旁参 / 被DTS否决**。转 jsonl 时映射为 `authority`：准→primary，旁参→support，被DTS否决→vetoed。

**"与刘本相左"判定标准**（满足任一即视为相左）：

| 条件 | 示例 |
|---|---|
| 结论相反 | 刘本"五阳从气不从势" vs 他书"从财从杀从儿从势从旺"五分 |
| 条件相反 | 刘本"只看月令是死法" vs 他书"月令为第一判据" |
| 优先级相反 | 穷通"调候＞格局＞旺衰" vs 刘本"中和为归" |
| 概念专有 | 子平"月劫格"，刘本无 |
| 出处错误 | 某主张本属刘本被误挂他书，或反之 |

判定结果记录：每条"被DTS否决"须记冲突对象/类型/判定人/日期。

#### 推理层（DTS-Arbiter）

- **规则⓪（域前置）**：先判争议双方是否在同一病域。跨域→两域并行；同域→进①②③④
- **规则①（最高优先）**：同议题有 `authority=primary` 时以 primary 为准
- **规则②（刘本未涉及）**：按条文直接性 + 取材密度顺位择优
- **规则③（旁参内互斥）**：条文直接性优先，取材密度顺位为辅
- **规则④（vetoed）**：不参与正向匹配

### 2.4 GAP 登记机制

**GAP = 准神依据缺口。** 当某议题在锁定底本中无 primary 切片时，不得脑补，须登记 GAP。

**登记位置**：`00_元数据/G1-A_Ontology/准神依据缺口登记_Authority_Gap_Registry.md`

**已登记 GAP**：

| 编号 | 议题 | 缺口性质 | 处置 |
|---|---|---|---|
| GAP-001 | 偏印格细则无 primary | DTS 切片中偏印细则 0 命中 | 走规则②，不新切 |
| GAP-002 | 偏财格细则无 primary | 同上 | 走规则② |
| GAP-003 | 病域归属字段缺失 | 全库切片无该字段 | 分层补标 P0/P1/P2 |
| GAP-004 | 化气格四要件未实装 | DTS 化象章有五路明文，引擎未接 | 待建 |

**GAP 的效力**：GAP 生效期间，该议题结论一律标 `authority=support`，不得标 primary。

### 3.2 版本选择备忘录

**存放位置**：`00_元数据/版本选择备忘录/`

### 3.3 版本分歧处理与来源字段解析

**并列收录，标"版本分歧"，不强行统一。**

**判据优先级**：

| 优先级 | 判据 | 适用条件 |
|---|---|---|
| **1（硬约束）** | **版本选择备忘录** | 底本锁定版本优先 |
| **2（默认）** | **最古本原则** | 两版完整度相当 |
| **3（例外）** | **完整性判据** | 三条件同时满足 |

**完整性判据的三条件**：① 早版残缺　② 晚版是同一底本内的补充　③ 晚版覆盖完整概念。

**实证**：`MEDICINE.YONG_SHEN.HUA_SHEN.006` 化气十段锦——正文内赋文仅甲己二段（行 4920），补遗·第163章十段全（行 7131-7151）；三条件满足，取补遗版。

**来源字段解析规则**：

**来源字段解析必须区分主源与参校源，参校源不得作为归属依据。**

```
✅ 正确：
  「渊海子平 第187章 玄机赋（全文）；参校 神峰通考 行9087-9090（节引）」
  → 主源 = YHZP   ← 归属依据
  → 参校源 = SFTK ← 仅作对照

❌ 错误：抓到"神峰通考"就归 SFTK
```

### 4.3 病域 / 药域归属值定义

`病域归属` / `药域归属` 是**字段取值**，不是 Domain 定义。

| 归属值 | 含义 | 适用范围 |
|---|---|---|
| 旺衰病域 | 身强身弱类病机 | `PATHOLOGY.QIANG_RUO` |
| 结构病域 | 十神组合类病机 | `PATHOLOGY.JIE_GOU` |
| 气候病域 | 寒暖燥湿偏枯 | `PATHOLOGY.QI_HOU` |
| 格局病域 | 格局成败 | `PATHOLOGY.GE_JU_BING` |
| 五行病域 | 五行偏枯/源流 | `PATHOLOGY.WU_XING_BING` |
| **CROSS_CUTTING** | 病药总纲，横切多域 | `PATHOLOGY.ZHI_FA` 总纲、`MEDICINE` 总纲 |
| **横切约束** | 约束所对病域的取值 | `JI_SHEN` |
| 非病药 | 与病药无关 | FOUNDATION/STATE/STRUCTURE 等 |

**CROSS_CUTTING 三条约束**：

1. **不是域** —— 不新增 sub-domain，G1-A 的 11 Domain 不变
2. **规则层必须指定作用域** —— 引用 CROSS_CUTTING 切片的规则，必须显式声明作用于哪一域
3. **不直接触发匹配** —— 不参与 `ge_jie_layer` 分支匹配，与 `DUANYU` 同级

## 七、切片分型

| 类型 | 定义 | 用途 |
|---|---|---|
| **规则型** | 四问齐全：对象+关系+条件+结果 | 直接转 jsonl |
| **原则型** | 四问不全，但语义明确 | 进 MD 文库，供上层规则引用 |

**原则型的工程表示**：命名常量 + 依据字段。命名常量名 = 切片 ID。

**依据链次序固定**：先挂 DTS 刘本原文（准神），再挂余书旁参。

## 九、质量标准

| 检查项 | 合格标准 |
|---|---|
| 原文完整性 | 不截断、不删节 |
| 原文真实性 | 确实来自该经典 |
| **原文可定位** | 能在锁定底本中定位（须人工复核） |
| 版本正确 | 对齐锁定底本 |
| ID 唯一 | 格式正确 |
| 类型明确 | 规则型/原则型 |
| 准神归属正确 | 标注为"准/旁参/被DTS否决" |
| 病域归属正确 | 五域之一 / CROSS_CUTTING / 横切约束 / 非病药；跨域须拆分 |
| 适用范围明确 | 全局/日主/月令/格局 |
| Category 正确 | 对齐 G1-A ontology |
| 无语义脑补 | 结论都是原文说的 |
| 无现代文混入 | 白话译文不进 canonical |
| 无水印噪音 | 没有页眉/页码/网站水印 |
| 章节定位 | 能精确定位 |

```
AI捞候选
  ↓
人工粗筛
  ↓

  ↓

  │   ⚠️ 禁止用多探针策略的并集 / 交集作判据
  │   ⚠️ 报出必须人工复核后才定性
  │   ⚠️ 比对前须统一：BOM、全半角、markdown 标记、注疏标签
  │   ⚠️ DUANYU 赋文层豁免覆盖率要求
  ↓
字符层检查
  ↓
语义层检查
  ↓
准神归属检验
  ↓
病域归属检验
  ↓
分型检验
  ↓
合格 → 进 MD 文库
不合格 → 标"待确认"，不进
  ↓
全部切完后，逐本逐章复查
  ↓
跑关联切片双向检查脚本
  ↓
100% 合格后 → 批量转 jsonl
```

### 10.1 探针策略 5 条前置约束

| # | 约束 | 理由 |
|---|---|---|
| **1** | 脚本报「未命中」**不得**直接判定切片有误 | 假阳性率 **99.6%** |
| **2** | **禁止**用多个探针策略的报出**并集**或**交集**作判据 | 并集假阳性 255/256；交集仅 14 条 |
| **3** | 报出「未命中」的切片**必须人工复核**后定性 | 唯一真缺口 1 条系误判 |
| **4** | 探针比对前须统一：BOM / 全半角 / markdown 标记 / 注疏标签 | 四类边界差异是假阳性主因 |
| **5** | **DUANYU 赋文层豁免覆盖率要求** | 赋文体例：正文与逐句夹注交替连排 |

### 10.2 实证脚注

| 对比 | 报出 | 真缺口 | 假阳性率 |
|---|---|---|---|
| 三 original 脚本并集 | 256 | 1 | **99.6%** |
| `audit_md_reverse.py` | 161 | 1 | **99.4%** |

### 10.3 执行细则：八条强制卡点

**§10.1 的 5 条约束是「应当」，缺执行层卡点。故立八条卡点。**

#### 卡点一：探针 bug 优先假设

**报出异常时，先假设探针有 bug，再假设内容有问题。**

#### 卡点二：探针未命中 → 强制双验证

```
探针报「未命中」
  ↓
验证 A：查外部权威版本
  ↓
验证 B：回锁定底本人工逐字核对
  ├─ 底本中有 → 探针 bug，修探针，不动内容 ✅
  └─ 底本中无 → 可下「内容有误」结论，须写明三条依据
```

#### 卡点三：引擎能力盘查不得仅凭字符串搜索

见架构层 §6。

#### 卡点四：引擎实现不得引入浮点

见架构层 §6。

#### 卡点五：AI 搜索的固定定位与三条边界

| 边界 | 内容 |
|---|---|
| **只作旁证** | 最终定性必须回锁定底本逐字核对 |
| **多源一致 ≠ 准神** | 四源一致只说明「流传广」 |
| **外部版本 ≠ 锁定版本** | 差异登记为「版本分歧」 |

#### 卡点六：脚手架先核对再下结论

| # | 检查项 | 要求 |
|---|---|---|
| 1 | **案例对位** | 打点用的 case_id 与 bazi 必须回案例表核对 |
| 2 | **不造替身** | 不得自造映射替代引擎函数 |
| 3 | **结论后置** | 不得在数据核对完成前给出否定结论 |
| 4 | **落盘为准** | 统计以落盘 JSON 为准 |

**探针有 bug 会假阳性；脚手架有 bug 会假结论。**

#### 卡点七：数据读取不得手动转写

| # | 检查项 | 要求 |
|---|---|---|
| 1 | **来源** | UTF-8 落盘文件 |
| 2 | **工具** | `read` 工具 |
| 3 | **禁用** | `Get-Content` / `cat` 等可能产生编码转换的工具 |
| 4 | **禁止转写** | 禁止对控制台输出做任何「手动解码」 |
| 5 | **乱码即换工具** | 必须换工具重读 |
| 6 | **数据来源声明** | 每条结论**必须声明数据来源**；不声明来源的结论，不采信 |
| 7 | **建议改动前先核数据结构** | 先核该字段**是否存在于预期的层级** |

**为什么它绕过全部现有卡点**：乱码是**合法输出**，不触发任何异常。

#### 卡点八：定稿前必须核分类口径的规范授权

| # | 检查项 | 要求 |
|---|---|---|
| 1 | **口径授权** | 先核所依据的分类**是否授权** |
| 2 | **引擎不作依据** | **引擎输出不得直接作口径依据** |
| 3 | **未授权即撤回** | 未授权口径 → **定稿撤回** |

**与卡点七的分工**：
- 卡点七管**数据读取**（来源可追溯、是否乱码转写）
- 卡点八管**依据合法性**（来源正确 ≠ 依据被授权）

### 10.4 违规案例

**六轮共十次错误**（第六轮为**卡点七拦住的正面案例**）。

#### 第一轮：凭探针结果下「内容有误」结论（三次连错）

| # | 错误结论 | 实际 |
|---|---|---|
| 1 | `XI_JI.011` 是伪句/编造 | 原文真实，**四源一致** |
| 2 | 锁定底本漏了那一句 | 底本**完整**含该句 |
| 3 | 探针失败 → 结论不可信 | 探针 bug：`【原注】` 前缀 + `……` 导致首块失配 |

**三次都先假设「内容有问题」，三次都是探针问题。** → 立卡点一、二。

#### 第二轮：凭字符串搜索下「未实现」结论

| 错误结论 | 实际 |
|---|---|
| 「五域并行完全没实现」 | `yongshen_multi_track.py` docstring 第一行即写明四轨并行层已实现 |

→ 立卡点三。

#### 第三轮：脚手架层推断先于核对（三次连错）

| # | 错误结论/动作 | 实际 |
|---|---|---|
| 4 | 打点时取 `辛巳 壬辰 乙亥 壬午` 当作「PZ-0016」 | 该八字属 **PZ-0081** |
| 5 | 自造十神映射判断 `正印=[]` | 引擎 `ten_god` 与复现不一致 |
| 6 | 据此宣布「矛盾不存在」 | 结论基于错误案例 + 错误映射 |

#### 第四轮：数据读取手动转写乱码（一次，绕过全部既有卡点）

| # | 错误结论/动作 | 实际 |
|---|---|---|
| 7 | 把 GBK 乱码「从官格」凭印象读成「从儿格」 | PZ-0125/0155/0166 实为**从官格**；PZ-0260 实为**从儿格** |

**唯一一次「已核对但读错」，也是唯一绕过全部现有卡点的一次。** → 立卡点七。

#### 第五轮：前提未核，用非授权口径做定稿（一次）

| # | 错误结论/动作 | 实际 |
|---|---|---|
| 8 | 按 `cong_type` 四值分档定稿 | v1.6 §7.6 只授权「真从/假从」；四分法无授权 |

**四轮「核对」全部通过，唯独没有一步核授权。** → 立卡点八。

#### 第六轮：建议改动前未核数据结构（一次，**卡点七生效的正面案例**）

| # | 错误结论/动作 | 实际 |
|---|---|---|
| 9 | 建议把 `ge_jie_layer.py:89` 改为「直接读 `sp['side']`」 | `side` 不是顶层键，直读会 KeyError |

**六轮里唯一一次「卡点拦住」而非「卡点没拦住」。**

#### 共性根因

| 错误类型 | 共同点 |
|---|---|
| 三次探针错误 | 凭工具输出下对象结论 |
| 一次盘查错误 | 凭工具输出下对象结论 |
| 三次脚手架错误 | 凭推断下结论 |
| 一次数据读取错误 | 凭印象转写乱码 |
| 一次口径错误 | 前提未核 |
| 一次结构错误 | 建议改动前未核数据结构（已被卡点七拦住） |

**工具的输出不等于对象的事实；推断也不等于数据；乱码的输出更不等于数据。**
