## 一、问题诊断：agent为什么绕圈

### 1.1 三个已确认的绕圈根因

|根因|表现|案例|
|-|-|-|
|**拿最终good/bad考核单层**|其他层没建全，单层永远不合格|调候层建了，但流通层没建，good/bad分歧率降不下去|
|**跨书混调**|PZZQ判据套DTS案例|拿"格局成败"去解释"两气成象"|
|**试图单维定吉凶**|旺衰/印/调候都试过|三次交叉表证明：bad在各档均匀占\~1/4|

### 1.2 核心矛盾

**你定的“按书分层建设、最后统一”——但考核时又拿“最终good/bad分歧率”去逼单层。**

**这两者直接矛盾：**

```
其他层（岁运/流通/调候/格局）没建全前
  → 任何单层都不可能让分歧率归零
    → 分歧率衡量不了单层质量
      → 只会逼出“银弹判据”
        → 一次次撞墙
```

### 1.3 案例的真实定位

|错误定位|正确定位|
|-|-|
|案例=标准答案库|**案例=理论演示实例**|
|断语=最终判决|**断语=演示用语**|
|用分歧率评判引擎对错|**用分歧率诊断引擎缺哪个理论模块**|
|追求分歧率降到0|**追求每层理论模块建全**|

|**SMTH 三命通会**|组合、神煞|部分未建|组合吉凶|

### 3.2 分层对标的铁律

**铁律一：案例只对本书的层**

* DTS案例→对DTS体用流通层
* PZZQ案例→对PZZQ格局层
* QTBJ案例→对QTBJ调候层
* **不跨层对标**

**铁律二：每层只对本层负责**

* 调候层不对"格局成败"负责
* 格局层不对"寒暖燥湿"负责
* 各层独立输出

**铁律三：各层对标完后，统一综合**

* 六层全部建好→综合
* 综合时才用good/bad
* 综合前不用good/bad逼单层

### 3.3 案例权威性分级

|级别|来源|用途|
|-|-|-|
|**准神级**|DTS刘本正文、PZZQ原文、SFTK原文、SMTH原文|直接对标|
|**旁证级**|DTS任铁樵注、QTBJ后人注|参考，不作唯一依据|
|**待核**|来源不明的案例|单独标注|

**注意：DTS案例全部来自任铁樵版本——任注是旁证，不是准神。DTS案例的断语，不能直接当准神依据。**

## 四、喜忌对标方法

### 4.1 对标的核心：从"吉凶"转向"喜忌"

|维度|吉凶|喜忌|
|-|-|-|
|判定对象|人生结果|命局药方|
|判定依据|good/bad标签|喜X忌Y|
|可验证性|低（同八字不同命）|高（药方有原典依据）|
|用途|最终结论|地基层|

**喜忌是地基层，吉凶是综合层。喜忌不准，吉凶必错；喜忌准了，吉凶才有意义。**

### 4.2 喜忌提取方法

**从原断提取喜忌，需要把原文表述标准化：**

|原断表述|标准化喜忌|
|-|-|
|"用财"|喜财|
|"财旺生官"|喜官、财|
|"印绶太旺"|忌印|
|"比劫夺财"|忌比劫|
|"寒木需火"|喜火（调候）|
|"两气成象，宜泄"|喜泄（流通）|
|"煞重身轻"|忌煞、喜印比|

**每个案例的喜忌提取，要标注来源（原断原文），不脑补。**

### 4.3 喜忌对标方法

**引擎输出喜忌字段：**

```
引擎输出 = {
    'ge\_cheng': 格名,
    'ti\_wx': 格体五行,
    'xi\_wx': 喜神五行,
    'ji\_wx': 忌神五行,  # 需补
    'climatic\_yongshen': 调候用神,  # 需补
    'flow\_yongshen': 流通用神,  # 需补
    ...
}
```

**对标维度：**

```
对标：
  ├─ 引擎xi\_wx vs 原断"喜X"
  ├─ 引擎ji\_wx vs 原断"忌Y"
  ├─ 引擎climatic\_yongshen vs 原断"需火/需水"
  └─ 引擎flow\_yongshen vs 原断"宜泄/宜通关"
```

**对标结果分类：**

|类型|含义|处置|
|-|-|-|
|**一致**|引擎喜忌 = 原断喜忌|通过|
|**方向一致但粒度不同**|如引擎说"喜金"、原断说"喜官杀"|可接受|
|**不一致**|引擎喜忌 ≠ 原断喜忌|追根因|
|**原断无喜忌表述**|原断只讲吉凶，没讲喜忌|跳过（不可对标）|

## 五、五域并行执行

### 5.1 病药五域并行

**配套 v1.7 切片规范，病药层分五域：**

|病域|判据|对应案例|
|-|-|-|
|旺衰病域|身强身弱|DTS/SFTK案例|
|结构病域|十神组合|SFTK/PZZQ案例|
|气候病域|寒暖燥湿|QTBJ/DTS案例|
|格局病域|格局成败|PZZQ/DTS案例|
|五行病域|五行偏枯|DTS案例|

### 5.2 域间并行，不互相否决

**每个案例在五域都输出，不互相否决：**

```
案例：冬月甲木，格局正官格成，但寒木无火不发

引擎输出：
  ├─ 旺衰病域：身弱，财多身弱（轻）
  ├─ 结构病域：无病
  ├─ 气候病域：寒（重）
  ├─ 格局病域：格成，无病
  └─ 五行病域：无病

综合：格局成（此域吉），寒为病（此域凶），需火暖
药方：扶抑药（印比）+ 调候药（丙火），并列
```

**关键：五域并行，不选"唯一主病"。**

### 5.3 域内主次裁决

**同一域内多个病机时，按序数等级裁决：**

|等级|含义|裁决依据|
|-|-|-|
|0 无病|该域无病|—|
|1 轻|有病但轻|病机轻|
|2 中|有病，影响层次|病机中|
|3 重|有病，格局受损|病机重|
|4 极重|有病，命局偏枯|病机极重|

**域内主次裁决依据：**

* DTS源流章"最多最旺者为源头"
* 病重药轻 vs 病轻药重
* 药之有无

## 六、执行流程

### 6.1 总体流程

```
第一步：按书拆分案例
  ├─ DTS\_clean.jsonl
  ├─ PZZQ\_clean.jsonl
  ├─ QTBJ\_clean.jsonl
  ├─ YHZP\_clean.jsonl
  ├─ SFTK\_clean.jsonl
  └─ SMTH\_clean.jsonl

第二步：按书分层对标
  ├─ DTS案例 → DTS体用流通层
  ├─ PZZQ案例 → PZZQ格局层
  ├─ QTBJ案例 → QTBJ调候层
  └─ ...

第三步：每层内按域拆分
  ├─ 格局层：格成/破 + 喜忌
  ├─ 调候层：用神得力/失用
  ├─ 体用流通层：源流归路
  └─ ...

第四步：逐案对标
  ├─ 从原断提取喜忌
  ├─ 引擎输出喜忌
  └─ 比对 + 标注一致/不一致

第五步：不一致案例追根因
  ├─ 成格路径漏？
  ├─ 喜忌输出错？
  └─ 格局判定错？

第六步：修完跑该层全量案例
  └─ 看喜忌一致率

第七步：六层全部建好后，综合
  └─ 综合时才用good/bad
```

### 6.2 单书执行清单

**以PZZQ为例：**

```
1. 加载PZZQ\_clean.jsonl（179条）
2. 逐条提取原断喜忌（人工+AI辅助）
3. 引擎输出每条的喜忌
4. 比对
5. 标注不一致案例
6. 追根因
7. 修完跑全量
8. 看喜忌一致率
```

**其他书同理，只是对标层不同。**

### 6.3 执行顺序

**按你之前定的顺序：**

|顺序|书|理由|
|-|-|-|
|1|PZZQ|格局层最熟，收口快|
|2|DTS|漏判最多，硬缺口|
|3|QTBJ|误报最多，量最大|
|4|SFTK|病药部分建|

## 七、验收标准

### 7.1 单层验收标准

**不是"分歧率降到X%"，是"喜忌一致率达标"：**

|层|验收指标|
|-|-|
|格局层|PZZQ案例喜忌一致率≥X%|
|调候层|QTBJ案例调候用神一致率≥X%|
|体用流通层|DTS案例源流归路一致率≥X%|
|病药层|SFTK案例病机一致率≥X%|

**X的具体值，按每层收口时的实际水平定——不预设"必须100%"。**

### 7.2 单层验收的判定

```
单层验收通过：
  1. 该层喜忌一致率达到稳定水平
  2. 不一致案例全部有根因分类
  3. 不一致案例中"引擎错"的比例 < "原断无喜忌表述"+"案例权威性不足"
  4. 0崩溃0异常

单层验收不通过：
  → 回到该层继续修
```

### 7.3 综合验收标准

**六层全部建好后：**

```
综合验收：
  1. 各层喜忌一致率均达标
  2. 综合输出的五域病机+药方，与原断各域表述一致
  3. 综合good/bad方向一致率（此时才用）
  4. 边界案例（同八字不同命）单独统计
```

## 八、反例与边界处理

### 8.1 反例来源

|来源|处理|
|-|-|
|**原断与引擎相反**|优先处理，追根因|
|**同一八字不同书原断相反**|归档，不作单一依据|
|**原断本身存疑**|标"存疑"，不参与对标|
|**版本异文**|并列收录，不强行统一|

### 8.2 反例的判定标准

```
反例分类：
  ├─ 引擎错 → 修引擎
  ├─ 原典分歧 → 登记，选体系
  ├─ 规则例外 → 补例外条件
  └─ 阈值边界 → 校准阈值
```

### 8.3 同八字不同命的处理

**同八字不同命，原因至少六种：**

|原因|引擎能否处理|
|-|-|
|出生地|❌|
|性别|✅|
|大运/流年|✅|
|家庭背景|❌|
|个人选择|❌|
|时代/社会|❌|

**同八字不同命的案例，单独建"边界测试集"：**

* 用途：测试引擎输出一致性 + 边界标记能力
* 不用于：回归校准（无唯一正确答案）

## 十一、一句话总结

**案例是理论演示实例，不是标准答案。对标的是喜忌，不是吉凶。分层对标，分域并行。单层验收用喜忌一致率，综合验收才用good/bad。地基层（喜忌）不能错，喜忌准了，吉凶才有意义。**

## 十二、防绕圈三条铁律

1. **不用good/bad逼单层**——其他层没建全，单层永远不合格
2. **不跨书混调**——DTS案例对DTS层，PZZQ案例对PZZQ层
3. **不试图单维定吉凶**——五域并行，各域独立输出

**记住：绕圈不是因为判据不对，是考核方式错了。换考核方式，绕圈自然解开。**
