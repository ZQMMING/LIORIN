### 已发现的潜在缺陷（因未接线，当前不影响生产）

1. `interpretation.py:418-421`
   ```python
   def _compute_evidence_closure(self) -> float:
       """计算证据闭合度。"""
       # TODO: 从 algorithm_rules 表查询
       return 0.85  # 简化版
   ```
   硬编码 0.85 冒充「计算」。且 `_compute_confidence()` 以
   `0.85 * 0.6 + input_completeness * 0.4` 合成置信度，
   意味着任何命盘的置信度都被这个常数锚定。
   **接线前必须先实现真实闭合度算法，否则等于把假数上线。**

## 四、本轮扫描的其它发现

- `canonical.py:562` / `:581` 两处 `except Exception: return None`
  （`_compute_hua_gong` 与 `_compute_seasonal_hexagram`）：
  属调用方**自身降级策略**，与 `jiehhou.get_current_jieqi_info`
  已修好的「只捕 ImportError」不冲突——后者管的是「缺依赖 vs 算错了」
  的区分，前者是这一层的容错。**保持现状**。
- `guajie.py` 内多处 `except Exception` 均带 `gj.evidence.append("…计算跳过（{exc}）")`，
  即失败会**留痕到 evidence**，不会静默。**保持现状**。

## 五、结论与建议

当前河洛的**算卦链**（先天→元堂→后天→大运→四层时间轴→卦爻解释→解卦）
是完整且经过回归的；**未接入的是「解读／证据／状态」这一层**，
共 2463 行，其中 `frozen_state` + `evidence_producer` + `diagnosis_rule_graph`
三位一体且已有 Golden Case 校验，是最成熟的一组。

建议接线顺序（每步独立可回滚）：

1. **`frozen_state` + `evidence_producer` + `diagnosis_rule_graph`**
   —— 已有 Golden Case 与专属测试，接线后风险最低、收益最直接。
2. `guidance` / `metrics_v2` —— 无专属测试，接线前应先补测试。
3. `canping` —— 需先定「参评诗断怎么按命盘定位」的规则，
   属产品口径问题，不只是技术接线。
4. `interpretation` / `hexagram_state` —— **必须先补掉硬编码与简化规则**，
   否则是把假数上线，明确排在最后。

> 本盘点不改动任何生产代码。所有接线都会改变 API payload 契约，
> 需用户确认目标后再动。
