日期：2026-10-06
支线：`feature/heluo-guajie-wiring-20261006`

## 一、问题

排盘链路只做到「算卦」为止，**卦象解析层从未执行**。

`HeluoResult` 自带 `guajie: dict | None = None` 字段，但生产排盘路径恒为 `None`：

- `ComputeStage._compute_heluo_yi` 走 `heluo_canonical.calculate()` 直调，
  绕过 `HeluoAdapter`；
- 而 `build_guajie_from_result` 的**全仓唯一生产调用点**在
  `src/tongshu/engines/heluo_adapter.py:136`，该 adapter 仅被
  `tests/heluo/test_heluo_jingyi.py` 使用。

结果，下列 4,000+ 行解析层代码在真实排盘中一行都没跑过：

| 模块 | 行数 |
|---|---|
| `guajie.py` | 2310 |
| `metrics_v2.py` | 537 |
| `guidance.py` | 365 |
| `diagnosis_rule_graph.py` | 333 |
| `evidence_producer.py` | 200 |
| `hexagram_state.py` | 228 |
| `frozen_state.py` | 197 |
| **合计** | **≈ 4170** |

## 二、改法

### 1. 填 `HeluoResult.guajie`（而非给 ComputeResult 加字段）

`api/app.py:284` 的 `_yi_block()` 用 `dataclasses.asdict(result.heluo_result)`
序列化整个 `HeluoResult`，故 guajie 一填即自动进 API 响应，
**无需改动 `ComputeResult` / `PipelineResult`**，改动面最小。

### 2. 应期参数逐层透传

| 层 | 参数 | 含义 |
|---|---|---|
| `TONGSHUPipeline.run()` | `heluo_target_date: date \| None` | 公历应期日，默认 `analysis_date` |
| | `heluo_target_hour: int \| None` | 时辰序号 1–12（子=1），`None` = 不解流时应期 |
| `ComputeStage.run()` | 同上 | 透传给 `_compute_heluo_yi` |
| `ComputeStage._compute_heluo_yi()` | `target_date` / `target_hour` | 实际调用解卦 |

此前这两个参数只加到了 `ComputeStage.run()`，`pipeline.run()` 不接收
（传即 `TypeError`），本轮补齐。

### 3. 公历 → 农历换算

新增 `ComputeStage._heluo_lunar_target()`，把公历应期日换算为
`(流年公历年, 农历月, 农历日)`。

**为什么必须换算**：河洛流月/流日以**农历**月日与月令「节」对齐
（`canonical._LUNAR_MONTH_JIE` 与 `compute_liuri` 的 `jie_datetime`），
直接传公历月日会整体错位一个月。换算失败时回退公历口径，不抛。

实测换算：

| 公历 | → 河洛口径 |
|---|---|
| 2026-08-17 | (2026, 7, 5) |
| 2026-01-20 | (2026, 12, 2) |
| 2026-02-04 | (2026, 12, 17) |

（农历年可能早于公历年——2026-02-04 落在农历乙巳年十二月。）

### 4. 按需单点，绝不全量

`build_guajie_from_result` 是 `target_*` 单目标设计，实测热态
**min 0.76 ms / median 1.16 ms / max 1.57 ms**（20 次）。

**绝不对 93 个流年全量跑**：按 1 ms/次外推即 +93 ms，会吃掉此前算卦
优化的全部收益。测试 `TestSingleTargetNotFullScan` 断言单盘调用次数恰为 1。

### 5. 解卦独立降级域

H8 段自带独立 `try/except`，日志可区分「H8 解卦降级」与「河洛/Yi 整体降级」。

**实测更正**：初版注释称「合并 try 会让解卦异常把整个河洛分支打成 None」——
经实测**不成立**，因为外层 `except` 并不重置已赋值的局部变量。
故此处的独立 try 是**可观测性收益，不是正确性依赖**，注释已按实况更正。
