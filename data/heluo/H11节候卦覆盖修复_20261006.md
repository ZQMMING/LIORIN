# H11 节候卦覆盖修复

日期：2026-10-06
支线：`feature/heluo-h11-jiehhou-coverage-20261006`

## 一、问题

`get_current_jieqi_info()` 的 docstring 声称「使用 sxtwl 查找**最近一个已过节气**」，
实现却与之不符：

```python
d = sxtwl.fromSolar(year, month, day)
jq_idx = d.getJieQi()
if jq_idx < 0 or jq_idx > 23:
    return None
```

而 `Day.getJieQi()` **只在交节当天返回索引**，其余日期一律返回哨兵 `255`。
结果是节候卦一年只有约 24 天可取、354 天直接判 `None`。

生产后果：`HeluoResult.seasonal_hexagram` 绝大多数时候是 `None`，
H11 节候卦整层形同虚设。`evidence_producer` 第 7 项（H11 节候卦事实）
也因恒为空而从不产出。

## 二、哨兵值实证

先确认分派依据可靠，再动代码。全量扫描 1970-01-01 ~ 2050-12-31：

| 指标 | 实测值 |
|---|---|
| 总天数 | 29,585 |
| `getJieQi()` 落在 0..23 的天数 | 1,944 = **81 年 × 24 节气**，无一例外 |
| 落在 0..23 之外的取值分布 | `{255: 27641}` —— **有且只有 255** |
| 0..23 内出现过的索引 | 24 个，齐全 |

结论：`255` 是 sxtwl 稳定且唯一的「当日无交节」哨兵，可安全用作分派依据。
已固化为常量 `_JQ_NO_JIEQI_SENTINEL`，并加测试锁定（若上游改哨兵会立刻失败）。

## 三、修法：快路径 + 全表二分（向后完全兼容）

```
d = sxtwl.fromSolar(year, month, day)
jq_idx = d.getJieQi()
├─ 0 <= jq_idx <= 23        → 直接返回（交节当日，与旧实现逐字一致）
├─ jq_idx != 255            → 返回 None（其它非法值，维持旧契约）
└─ jq_idx == 255            → 查全表，取「日期不晚于目标日」的最近一个节气
```

全表来自 `sxtwl.getJieQiByYear()`。**注意其窗口是 [该年立春, 次年立春]**——
实测 `getJieQiByYear(2026)` 只返回 2026-02-04 ~ 2027-02-04 共 25 项，
**不覆盖 1 月**。故须合并 `(year-1, year)` 两年，合并后跨度为
`(year-1)立春 ~ (year+1)立春`，完整覆盖该公历年。

日界口径：交节当日即归入新节气（`日期 <= 目标日`），
与旧实现在 24 个交节当天的行为完全一致。

缓存：`_JIEQI_TIMELINE` 有界 FIFO（上限 64 年），
逐项 `popitem` 语义用普通 dict + 插入顺序实现，不引入 `OrderedDict`，
以免影响外部对模块全局的注入用法。

## 四、效果

| | 修复前 | 修复后 |
|---|---|---|
| 1984 全年节候覆盖 | 24 / 366 天 | **366 / 366 天** |
| 交节当日结果一致性 | — | **24 / 24 相符，0 不符** |
| 端到端 `HeluoResult.seasonal_hexagram` | 绝大多数 None | **全年有值** |
| 冷启动耗时（新年份） | — | 0.74 ms |
| 热态耗时 | — | 0.0036 ms |

端到端样本（1990-05-20 出生）修复后：
`立夏 / 火山旅 / 山天大畜 / 动爻 5`。

原典核验（冬至）：「一索得中男，颐六四爻动，为地雷复卦」——
实测冬至得 `主卦=山雷颐`、`变卦=地雷复`、`动爻=4`（六四），**吻合**。

对排盘链路的影响：run() 中位 105.6 ms（与修复前同量级，无回归），
JSON 载荷 1256 → 1257 KB。

## 五、顺带修：两处无界缓存

| 位置 | 原状 | 改为 |
|---|---|---|
| `canonical._jie_cache` | 无界 dict，实测跑到 124 年 / 1,488 条 | 上限 256，FIFO 淘汰 |
| `jiehhou._JIEQI_TIMELINE` | （本次新增） | 上限 64，FIFO 淘汰 |

出生年跨度可达数百年，长期服务会缓慢涨内存且永不回收。
刻意使用普通 dict（Python 3.7+ 保序）而非 `OrderedDict`，
以免 `move_to_end` 影响任何外部注入普通 dict 的用法。

## 七、查实后决定不动的项

- **`Timeline` 三死字段**（`monthly_hexagrams` 恒 `[]`、`hourly_hexagram` 恒 `None`、
  `daily_hexagram` 存先天卦且 `date` 是出生年字符串 `"1990"`）：全仓**零消费方**
  （测试里的同名 `daily_hexagram` 均为黄历字段，非河洛）。
  属契约清理，非算法缺陷，本轮不动。
- **`yearly[].yuantang_nature`**：类型为 `int`（取自**流年卦**该爻），
  而 `YuanTang.yao_nature` 为 `str`（取自**先天卦**）。经查这是**两套不同口径**，
  分别服务于 `compute_liuyue` 与 `interpret_all_liunian`，**并非 bug**，不动。
- **流日层改按需**（可再省 24.8 ms / 76% 载荷）：仍被
  `tests/test_heluo_context.py:91` 既有断言挡住，需用户豁免「禁改测试语义」。
