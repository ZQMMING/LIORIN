# V2.22-PATCH-001 Business Judgment State Model

> 状态：P0 / 必须纳入 V2.22
> 来源：Human 提供，2026-09-16 录入
> 铁律核心：**Boolean ≠ Business Judgment**；Rule Match State 与 Business Judgment State 严格分层

---

## 1. 修正目的

V2.22 原有：

```
MATCH
NO_MATCH
RULE_NOT_APPLICABLE
UNKNOWN
```

仅定义 Rule Match State。**不得**将其作为六经典最终业务裁决状态。
必须严格区分 **Rule Match State** 与 **Business Judgment State**，两者不得混用。

## 2. Boolean 使用限制

Boolean 仅允许用于纯技术属性：

```
is_present
is_missing
is_verified
is_paraphrase
cross_verified
requires_human_review
```

**禁止**使用 Boolean 作为最终经典业务裁决：

```
is_strong / is_weak / is_useful / is_pattern / is_successful
is_effective / is_disease / is_medicine / is_favorable / is_unfavorable
```

不得出现 `true=成立 / false=不成立` 作为唯一业务语义。

## 3. 三态最小模型

所有存在「成立/不成立/无法确定」语义的业务维度，至少使用：

```
YES
NO
UNDETERMINED
```

- YES = 明确成立
- NO = 明确不成立
- UNDETERMINED = 证据、事实或规则不足以形成确定裁决

**不得**把 UNDETERMINED 转换成 NO / FALSE / WEAK / ABSENT / FAILED。

## 4. 多态模型

经典原文存在不同性质/程度/作用方向/条件分支时，**不得**强行压缩成三态，必须建立专用 Enum。

```
Boolean → Tri-State → Multi-State
```

按经典语义选择最低充分状态集，不得为了代码方便减少枚举。

## 5. 状态类型必须分层

业务状态至少分为：

```
A. EXISTENCE_STATE    （存在）
B. CONDITION_STATE    （条件）
C. EFFECT_STATE       （效力）
D. STRENGTH_STATE     （强弱）
E. ROLE_STATE         （角色/作用）
F. PATTERN_STATE      （格局）
G. RESULT_STATE       （成败结果）
```

不同状态不得互相替代。例如：印存在 ≠ 印旺 ≠ 印有效 ≠ 印为用 ≠ 印成格，每项独立建模。

## 6. 强弱类状态

不得 `strong=true / weak=false`，必须：

```
strength_state =
    STRONG
    SLIGHTLY_STRONG
    NEUTRAL
    SLIGHTLY_WEAK
    WEAK
    UNDETERMINED
```

现有 V2.22 的 strength_state 保留，不得改回 Boolean。

## 7. 支持/印星/生扶类状态

不得只使用 `support=true/false`，至少允许：

```
NONE
WEAK
NORMAL
STRONG
EXCESSIVE
UNDETERMINED
```

必要时增加 OVER_SUPPORT / COUNTER_EFFECT，但**必须由具体经典 Rule 授权**，不得由工程人员自行解释。

## 8. Effectiveness 状态

不得 `effective=true/false`，统一使用：

```
EFFECTIVE
PARTIALLY_EFFECTIVE
INEFFECTIVE
BLOCKED
CONDITIONAL
UNDETERMINED
```

现有 effective/partially_effective/ineffective/blocked 可保留，但必须增加 conditional / undetermined。

## 9. 格局状态

不得 `pattern_exists=true/false`，必须采用专用 PATTERN_STATE：

```
NOT_ESTABLISHED
ESTABLISHED
CONDITIONAL
BROKEN
FALSE_FORM
UNDETERMINED
NOT_APPLICABLE
```

具体枚举只能由对应经典 Rule 注册。

## 10. 成败状态

不得 `success=true/false`，必须至少：

```
SUCCESS
FAILURE
CONDITIONAL_SUCCESS
PARTIAL_SUCCESS
BROKEN
UNDETERMINED
```

「格局成立」和「格局成败」必须是两个不同字段。

## 11. 病药状态

不得 `disease=true / medicine=true`，必须拆分 DISEASE_STATE / MEDICINE_STATE：

```
PRESENT
ABSENT
PRIMARY
SECONDARY
CONDITIONAL
COUNTERACTIVE
UNDETERMINED
```

具体取值必须绑定 Source / Rule。

## 12. 经典语义状态不得跨书强制统一

DTS 印旺 / PZZQ 印旺 / QTBJ 印旺 各自独立语义。不得因字段名相同强制同一业务语义。
必须保留：book_id / rule_id / concept_id / state_domain / state_value。

## 13. 关键示例（必须能同时存在）

```
DTS / 何知章：daymaster_state=WEAK, resource_state=LIGHT, judgment=...
DTS / 反局：  daymaster_state=WEAK, resource_state=EXCESSIVE, judgment=...
```

不得因 daymaster_state=WEAK 合并为 weak_resource=true；
不得因 resource exists=true 推出 resource_effective=true。

## 14. Rule Match State 与 Business State 严格分离

MATCH 只表示「该 Rule 前提条件匹配」，不表示格局成立/身旺身弱/用神/喜神/病/药/成/败。

```
Rule → MATCH → Business Judgment → Enum State
```

## 15. AND/OR 不得称为 Boolean Business Judgment

AND/OR 仅作为 Rule Preconditions 逻辑运算符，≠ Boolean Business Judgment。
禁止将 AND/OR、true/false 作为六经典业务结果的数据类型。

## 16. Enum Registry 强制要求

所有 Business Judgment Enum 必须登记：

```
enum_id
domain
engine
allowed_values
value_definition
source_ids
rule_ids
version
status
```

任何新 Enum 未注册 → STOP / UNKNOWN ENUM / WAIT_FOR_DECISION，不得由 Agent 临时创造。

## 17. Backward Compatibility

现有 MATCH/NO_MATCH/RULE_NOT_APPLICABLE/UNKNOWN 全部保留，归属 INTERNAL_RULE_MATCH_STATE。
新增 BUSINESS_JUDGMENT_STATE 作为业务输出层。两个层级不得合并。

## 18. Fail Closed

业务维度需 Multi-State Enum 而 Registry 无合法枚举 → FAIL_CLOSED。
不得 fallback → Boolean / true/false / LLM / score / nearest enum。

## 19. Acceptance Criteria（必须增加测试）

```
TEST-ENUM-001  Boolean 不得作为 Business Judgment 输出
TEST-ENUM-002  MATCH 不得直接等同于 YES
TEST-ENUM-003  UNKNOWN 不得转换为 NO
TEST-ENUM-004  同一 Concept 不同经典可以拥有不同 State Domain
TEST-ENUM-005  STRONG/WEAK 不得使用 Boolean 替代
TEST-ENUM-006  CONDITIONAL 不得自动转换为 YES
TEST-ENUM-007  RULE_NOT_APPLICABLE 不得进入 Business Judgment
TEST-ENUM-008  未注册 Enum 必须 FAIL_CLOSED
TEST-ENUM-009  Boolean-only schema 检查必须 FAIL
TEST-ENUM-010  经典原文存在多态语义时，必须使用 Multi-State Enum
```

## 20. 最终执行铁律

```
Boolean ≠ Business Judgment
MATCH ≠ YES
NO_MATCH ≠ NO
UNKNOWN ≠ NO
RULE_NOT_APPLICABLE ≠ NO
Existence ≠ Strength
Strength ≠ Effectiveness
Effectiveness ≠ Usefulness
Pattern Existence ≠ Pattern Success
Disease ≠ Medicine
Classic Concept ≠ Universal Semantic State
```

最终架构：

```
Canonical Fact
  → Rule Preconditions
  → Rule Match State
  → Business Judgment State
  → Evidence
  → Assertion
```

Rule Match State = MATCH / NO_MATCH / RULE_NOT_APPLICABLE / UNKNOWN
Business Judgment State = Tri-State / Multi-State Enum
**禁止 Boolean-only Business Judgment。**
