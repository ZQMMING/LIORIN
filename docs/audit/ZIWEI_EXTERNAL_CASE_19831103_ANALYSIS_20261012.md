## 二、该文的紫微批断章节结构（关键证据）

文章的紫微部分（原文第 198–391 行）章节划分：

```
紫微斗数批断
├─ 一、格局总览（融合三合派、飞星、钦天四化、河洛紫微多角度论断）

├─ 三、六大领域综合论断（健康、学业、事业、财运、人际、婚恋）
├─ 四、前八大限逐一大限+流年重点提示    ← 应期层
├─ 五、针对性解决方案与长期建议
└─ 六、总结论
```

## 三、结构分析：三层 + 一聚合

### 层级 1：宫位层（第 2 章「十二宫逐宫深度解析」）

12 宫：命宫 / 财帛 / 官禄 / 夫妻 / 迁移 / 疾厄 / 福德 / 子女 / 田宅 / 父母 / 兄弟 / 交友

逐宫给出：主星、生年四化、自化、三方四正、庙旺陷、建议。
**这是「空间分区」层。**

### 层级 2：体用层（第 1 章「格局总览」）

包含三类**跨宫**内容：

1. **格局**（第 210–213 行）：`杀破狼全局结构` —— 命宫七杀 + 官禄破军 + 财帛贪狼
   > 「杀破狼之人一生多变动、开创、不适合一成不变的死水环境……成败起伏大」
   → 格局是**多个宫的组合体**，不属单一宫。

2. **生年四化**（第 219–226 行，标题「全盘命脉」）：
   > 「破军【生年禄】官禄宫」「巨门【生年权】子女宫」「太阴【生年科】疾厄宫」「贪狼【生年忌】财帛宫」
   → 四化**挂载在宫上，但作为整体架构独立成节**。

3. **命身同宫**（第 227–232 行）：体用关系的具体化。

**这是「判断方法」层，不是「空间分区」层。**

### 层级 3：应期层（第 4 章「前八大限逐一大限+流年重点提示」）

按大限走 8 步，每步给基调 + 重点流年。
**这是「时间」层。**

### 聚合层：领域层（第 3 章「六大领域」）

`健康 / 学业 / 事业 / 财运 / 人际 / 婚恋` —— 这是**把十二宫内容按人生议题再聚合**。

> 对照我们 `domain_reading.py` 的 8 领域：`健康 / 学业 / 事业 / 财运 / 人际 / 婚恋 / 子女 / 父母`
> —— **前 6 个逐字相同**，我们多 2 个（子女/父母）。

## 四、结论

### 4.1 该文验证了「分层」而非「平铺」

紫微斗数的正确结构是：

```
宫位层（12 宫）  ── 空间分区
   ↓ 再聚合
领域层（6 领域） ── 人生议题聚合
   ↑
体用层（格局/四化）── 跨宫判断方法
应期层（大限流年） ── 时间演化
```

**格局 / 四化 / 应期 三者都是独立层级，不与十二宫并列。** 且行业实践（此文）**从不把它们叫「维度」，而叫「总览」「架构」「提示」**。

### 4.2 我们的错误确认

`DIMENSIONS_15` 把 `格局/应期/四化体用` 与十二宫并列为「15 个维度」——
**层级混淆，且命名不符合行业惯例。**

### 4.3 与我们引擎的映射

| 外部文章层级 | 我们引擎对应物 | 状态 |
|---|---|---|
| 宫位层（12 宫） | `interpretation.DIMENSION_ORDER`（12 维） | ✅ 已有 |
| 领域层（6 领域） | `domain_reading.py`（8 领域） | ✅ 已有，多 2 个 |
| 体用层（格局/四化） | `answer_layer` 的「格局/四化体用」桶 | ⚠️ 被误并入 dimensions |
| 应期层（大限流年） | `interpretation.decadal_table` + answer_layer「应期」桶 | ⚠️ 部分，被误并入 |
| （无对应） | `answer_layer` 的 12 宫位维 | 与 interpretation 12 维同构 |

## 五、修正方向（建议）

`answer_layer` 对外契约由：
```python
{"dimensions": [12宫 + 3议题], "answer": {...}, "summary": {...}}
```
改为：
```python
{
  "dimensions": [12 宫位维],        # 与 interpretation 12 维 1:1 对齐
  "answer": {12维 → 条目},
  "body_use": {                     # 体用层，独立字段，内容不删
      "格局": [...],
      "应期": [...],
      "四化体用": [...],
  },
  "summary": {...},
}
```

- **12 宫位维** 与 interpretation **真正对齐**（一宫一维）
- **体用三项**升为独立字段 `body_use`，不再混入 `dimensions`
- 命名符合文献与行业惯例（「体用」 vs 「维度」）
