# 河洛引擎 —— 包结构与部署说明（2026-10-24 结构性重构）

> **一句话**：河洛引擎现在是一个**自包含、可 `pip install` 到服务器独立运行**的
> 顶层包 `heluo_engine` —— 源码、数据、原典、依据文档全在一个文件夹里，
> **零路径绑定**，不再与主仓 `tongshu` 命名空间打架。

---

## 1. 为什么做这次重构

用户交付要求：**「河洛合并好一个，全部归到一个文件夹，路径依赖的都放到统一一个
文件夹，以后要放服务器上的，不能太存在路径绑定和路径依赖」**。

重构前实测到**两个硬伤**：

### 1.1 命名空间互斥（静默破坏）

河洛包 `pyproject.toml` 写 `name = "heluo-engine"`，但
`[tool.setuptools.packages.find] where = ["src"]` 实际装出的是**顶层包 `tongshu`** ——
与主仓顶层包**同名**，且 `engines/facts/reasoning/spec` 四个子包**同名重叠**
⇒ 两个 `tongshu` **不能同时 import**。

实测两种安装顺序：

| 顺序 | 后果 |
|---|---|
| 主仓 src 在前 | 河洛的 `canonical_signals` 消失 |
| 河洛包 site-packages 在前 | **主仓 32 个顶层子包全部消失**（`tongshu.signal` / `tongshu.pipeline_stages` / `tongshu.api` …），报错只说「找不到 tongshu.signal」，**不提示你装了河洛包** |

### 1.2 路径绑定（换层级即失效）

判词库定位靠 `Path(__file__).resolve().parents[4]` 反推仓库根再拼
`data/heluo/xxx.json`；参评语料靠 `os.path.join(dirname(__file__), "..", "..", "..", "..", "data", "heluo", "canping")`；
出生地点表靠 `parents[4] / "data" / "locations.json"`。

⇒ 换任何一层目录即失效；把河洛包**硬耦合**在主仓仓库结构上，**无法独立部署**。

> `guajie.py` 注释里引用的判据依据。放在包外 ⇒ 服务器上只有「结论」没有「证据」，
> 且守卫无法随包运行。

## 3. 零路径绑定怎么做到的

**统一入口**：`src/heluo_engine/_paths.py`

```python
PKG_DATA_DIR = _locate_pkg_dir("data")   # 运行时数据
PKG_ORIG_DIR  = _locate_pkg_dir("orig")   # 原典切片
PKG_DOC_DIR   = _locate_pkg_dir("docs")   # 依据文档
```

双通道定位：

1. **已安装形态**（服务器正常形态）：`importlib.resources.files("heluo_engine")`
   ⇒ 与安装位置、运行目录、CWD **全部无关**；
2. **源码树直跑**（本仓开发态，测试以 `from src.heluo_engine...` 导入）：
   顶层包名是 `src.heluo_engine` 而非 `heluo_engine`，`importlib.resources` 会
   ImportError ⇒ 退到 `Path(__file__).resolve().parent.parent / "data"`
   —— **包内相对路径**，同样不含任何仓库根推算。

出生地点表另有可配置链：**构造参数 > 环境变量 `HELUO_LOCATIONS_PATH` > 包内
`heluo_engine/data/locations.json`**；三者都找不到时抛 `LocationError`
（**不静默退化为空 registry**）。

## 4. 部署到服务器

```bash

pip install .            # 或 pip install heluo-engine
```

```python

ad = HeluoAdapter()
```

`pyyaml` / `jsonschema` / `pydantic` / `tzdata`。

## 5. 守卫（把「结构退化」变成 CI 红灯）

| 守卫 | 盯住什么 |
|---|---|
| `tests/heluo/test_heluo_deploy_package.py`（新，19 项） | 零路径绑定（`parents[N≥2]` / 机器绝对路径 / 旧布局字面量 / `..` 上跳，**只查可执行代码**）、数据定位唯一入口、随包三件套齐备且被 package-data 覆盖、**仓库外独立跑通一例完整算例** |
| `tests/heluo/test_heluo_package_identity.py`（改） | 顶层包名 = `heluo_engine`、`src/tongshu/` **不存在（含空目录）**、包发现只认 `heluo_engine*`、src 内零 `tongshu` 绝对导入、历史冲突已登记 |
| `tests/cross_repo/conftest.py`（新） | 主仓不可用 ⇒ 跨仓守卫整目录跳过（不再让独立包 CI 一片红） |

**变异演练**：11 项注入缺陷，**11/11 全部被抓住**（每次都先确认守卫会红，
而不是「看着对」）。

> ⚠ **写守卫的坑（本次实测踩到）**
> 1. **全文扫描会把注释里的历史说明误判成缺陷** ⇒ 断言必须落在**可执行代码**上
>    （`ast` 剥 docstring + 注释）。
> 2. **顶层 `find_spec("tongshu")` 会撒谎**：残留的空目录 `src/tongshu/` 会被 Python
>    当成**命名空间包**，`import tongshu` 成功却无任何子模块 ⇒ 判定主仓是否可用
>    **必须查具体子模块**（`tongshu.pipeline`）。
> 3. **关键词断言太弱**：`assertNotIn("_REPO_ROOT")` 换个变量名就绕过 ⇒ 改断
>    **赋值语句的形态**。

## 7. 跨仓测试的归置

`tongshu.pipeline_stages` / `tongshu.reasoning.signal_engine` /
`tongshu.engines.gua_jixiong` / 梅花易数），而这些模块**本包从来没有**。

> ⚠ 这 30 项**在重构前就存在**（已用 `git worktree` 在 HEAD `435622fd` 上复现：
> 19 failed + 11 errors），**不是本次重构引入的**。
