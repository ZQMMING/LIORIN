### 1.2 命名空间冲突（接线的真正拦路虎）

八字包名 `shuntian-bazi`、河洛包名 `heluo-engine`，**两者都提供 `tongshu.engines.*`**
（`tongshu/engines/bazi_engine.py` 与 `tongshu/engines/heluo/*` 同目录）。

**「让河洛/子平依赖八字包」这条路在现命名空间下走不通**，必须先解决命名空间。

## 2. 目标架构

```
        ┌───────────────────────────────┐
        │  shuntian-bazi（八字独立包）      │  ← 单一事实源：四柱 + 时间事实
        │  命名空间：shuntian_bazi（顶层）  │
        └───────┬───────────┬───────────┘
                │           │
     ┌──────────┴───┐   ┌───┴────────────┐
     │ 子平（ziping） │   │ 禄命法 / 盲派    │
     └────────────────┘   └────────────────┘

   ┌──────────────────────────┐    ┌──────────────────────────┐
   │ 黄历引擎（huangli）        │    │ 时间域（time_resolver）    │
   │ 农历/日柱/纳音/节气/宜忌   │    │ 时区/真太阳时/日界 23:00   │
   └───────────┬──────────────┘    └───────────┬──────────────┘
               │                                │
               └────────┬───────────────────────┘
                        ▼
                 ┌─────────────┐        ┌─────────────┐
                 │ 河洛（heluo）│        │ 紫微（ziwei）│
                 │ 流日卦按当前日│        │ 农历/时辰起盘│
                 └─────────────┘        └─────────────┘
```

### 2.1 八字包必须换到独立命名空间

`shuntian-bazi` 的公开入口改为**顶层包** `shuntian_bazi`：

```python
from shuntian_bazi import BaziEngine, BaziChart, BaziAdapter   # 五引擎统一入口
```

* 理由：现 `tongshu.engines` 命名空间与主仓/河洛/子平**三方重叠**，依赖化必冲突。
* 兼容期：`tongshu/engines/__init__.py` 保留旧路径 re-export（带 deprecation），
  各仓逐步切换；切换完成后删除 vendored 副本。
* 单一来源：所有修法（含 2026-10-22 儒略历口径）只进 `shuntian-bazi`，
  各仓**不再 vendored**（`vendor/tongshu` 与 `src/tongshu/engines/bazi_*` 全部删除）。

### 2.2 八字引擎的公开契约（冻结）

```python
class BaziEngine:
    def compute(self, solar_date: tuple[int, int, int, int],
                gender: Literal["male", "female"] = "male",
                skip_late_zi: bool = False,
                birth_datetime: Optional[datetime] = None) -> BaziChart: ...

class BaziChart:            # frozen dataclass
    year_pillar / month_pillar / day_pillar / hour_pillar: Pillar
    day_master / luck_pillars / xiao_yun_pillars / start_age
    birth_datetime / gender
    hidden_stems / branch_ten_gods / twelve_growth / nayin / shensha
    kong_wang / five_element_balance / …

class BaziAdapter:          # CalculationContext → BaziChart（时区/真太阳时/日界归它管）
    def compute(self, ctx: CalculationContext, gender: str = "male") -> BaziChart: ...
```

* `BaziEngine` 本身**不负责**时区/经度校正/EoT/日界 —— 那是 `BaziAdapter` 的职责
  （主仓 `bazi_adapter.py:1-18` 的自述），八字引擎的契约不得越界吞掉它。
* 下游引擎**不得自建** `BaziEngine()` 实例 —— 用单例 `canonical_bazi_engine`
  （主仓 `bazi_engine.py:2097-2101` 的既有约定）✓。

### 2.3 黄历引擎的注入契约（河洛侧已可直吃对象）

主仓 `HuangliEngine.get_day(date) -> HuangliDay`（dataclass），其 `to_dict()` 的
`day_ganzhi / lunar_month / lunar_day / day_na_yin / jie_qi / yi / ji` **七个字段
与河洛桥接层期望逐字同名** ✓；缺的只是「对象 → 注入」这一步。

**河洛侧已改**（`heluo_lunar_bridge._as_huangli_dict`）：桥接层现在
**同时吃 dict 与 dataclass**（有 `to_dict()` 就调）⇒ 平台侧接线只需一行：

```python
result = heluo_adapter.compute(
    solar_date=(1983, 11, 3, 12), gender="male",
    huangli_provider=lambda d: huangli_engine.get_day(d),   # ← 一行
)
```

用户裁决（2026-10-22）：**不要算流时卦，到流日为止；流日卦按当前日期自动算**。

河洛侧已落地：

| 落点 | 行为 |
|---|---|
| `heluo_adapter.resolve_target_date()` | 目标日优先级：显式 `target_date` > 显式三元 > **今天（北京时间）** |

| `guajie.build_guajie_from_result` | 未传 target 时回退到 `result.target_date` ✓ |
