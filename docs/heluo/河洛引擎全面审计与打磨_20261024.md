## 1. 审计怎么做的

### 1.1 三路并行

| 手段 | 覆盖 |
|---|---|
| 静默失效审计（explore） | 定义了无调用者的符号 / 算了没接进输出 / 恒假分支 / 死写入 / 恒抛分支 |
| 守卫盲区审计（explore） | 无守卫模块 / 只测存在性不测正确性 / 守卫可被绕过 / 边界未覆盖 / 数据层与引擎层缺口 |
| 端到端实跑体检（自做） | `HeluoAdapter.compute` 真实产出 → 递归扫描所有空值路径（49 处） |

### 1.2 端到端体检的发现

实跑 `compute((1990,6,15,14), target_date="2026-10-23")`，产出 3 条平台信号
（CYCLE_CONTEXT / DAILY_ACTIVATION ×2），判词层 25 个字段、evidence 53 条。

递归扫描出的 49 处空值路径，逐条判读后确认**绝大多数是设计如此**：

* `timeline.*.days = []` → 流日段是**惰性物化**（`materialize_month_days` 按需现算），
  非缺失；
* `guajie.liushi_*` 空 → 流时卦**生产层维持剥离**（用户裁决「到流日为止」）；
* `guajie.si_duan = []` → 本盘四段无断语，属正常。

**唯一存疑项** `timeline.*.days` 全空 —— 经逐条核对是惰性物化，非缺陷。

## 2. 审计结论的核实（3 条被推翻 / 修正）

审计报告不是圣旨。逐条回源码 + 实测后：

| 审计结论 | 核实结果 |
|---|---|
| 「gua6 口径在 `compute_daily_base_hex` 与 `compute_liuri_stub` 之间混用，两条路径算出不同流日卦」 | **推翻**。实测同一 (月,日) 两条路径**逐字一致**（6/6 日卦名 + 动爻全同）。`compute_daily_base_hex` 的 gua6 分支早已改用 `liuri_gua6_bases`（timeline_yun.py:679）。**唯一残留是 docstring 仍写旧口径**（已订正，见 §3.5） |
| 「`HL_HEXAGRAM_STRUCTURE` 每盘产出即被丢弃 —— 静默丢数据」 | **修正**。丢弃是**已披露**的（`dropped_rule_ids` → `dropped_rules()` 供调用方查，2026-10-07 审计已做）。真问题是「丢弃清单只有单向断言」，已改为双向（§4.4） |
| 「`yi` 字段完全可做原典逐字回查」 | **修正**。实测整串连续命中 **356/376**，另 8 条底本原缺、20 条是**跨段抽取**（原典文字都在，只是不相邻）。改用「整串 **或** 分句全覆盖」判定 → **376/376** |

**另外**：审计称 `sanyuan` 锚点偏移会导致三元错位 —— 实测**锚点 ±1 只影响 2 个边界年**
（1863 / 1923 / 1983 这类恰落在档位分界上的年），因为 60 与 180 的整除关系让
三元输出对档内偏移不敏感。守卫已按此事实设计（断「锚点年 + 相邻年」）。

## 3. 修的五处真缺陷

### 3.1 判词层失败被裸 `except: pass` 吞掉（`heluo_adapter.py`）

```python
except Exception:
    pass  # 解卦层失败不阻塞主链
```

失败时 `result.guajie` 保持 `None` → **下游看到「没有判词」却无法分辨**
「解卦层挂了」与「这盘本来就没判词」。缺失被当成正常，静默无痕。

**修法**：按 guajie 层自身的披露格式（`guajie.py:1859` 的 `{"error": ...}`）
挂上错误字典 —— 不阻塞主链，但错误**显形**。

### 3.2 `_KZ_ERRORS` 跨盘累积（`guajie.py`）

docstring 与 `kuozhan_errors()` 都声称「最近一次」，实际返回**进程级历史累积**：
第一盘失败过一次，之后每一盘都带着那条陈迹，调用方无法区分「本盘失败」与
「历史上有过一盘失败」。

**修法**：`_build_kuozhan` 入口 `clear()`（与 `build_diagnosis_graph` 的
`_DROPPED_RULES.clear()` 同款），语义与文档对齐。

### 3.3 `era` 静默回落无来源标记（`heluo_adapter.py` + `canonical.py`）

`chart.birth_datetime` 缺失时静默回落 `era="zhong"`。而 **era 决定寄宫对象**
（上元寄艮/坤、中元阳男阴女寄艮、下元寄离/兑）→ 寄宫数一变 → 先天卦变 →
元堂变 → 后天卦变 → **全链判词全变**，而下游无从判别真假。

**修法**：新增 `HeluoResult.era_source`（`explicit` / `derived` / `fallback`），
与既有的 `birth_year_source` 同一约定。

### 3.4 元气层异常静默降级（`canonical.py`）

`except Exception: yuan_qi = None` → 下游看到的 `yuan_qi=None` 无法分辨
「本盘确实无元气」与「元气层抛了异常」。化工链路已有同类自曝
（`hua_gong` 的「本级不可判」evidence），元气层此前没有。

**修法**：降级仍保留（不阻塞主链），错误写入新增的 `HeluoResult.yuan_qi_error`。

### 3.5 `gua6` docstring 与实现脱节（`timeline_yun.py`）

`_gua6_segment_to_days` 的 docstring 仍写「段本卦 = **链式** day_lines[k*6]」——
那是 2026-10-22 修正**之前**的旧口径（hou5 链式累变）。会误导后来者以为
链式仍是 gua6 的正确口径。

**修法**：订正为「月卦逐爻变（居位爻不动）」，并附旧口径的退化序列
（屯/鼎/屯/鼎/屯）与原典序列（屯、革、明夷、家人、蹇）作对照。

## 4. 补的四组守卫

### 4.1 `yi` 字段原典保真（`test_heluo_guajie_data_fidelity.py` 增补）

`yi`（爻辞释义）此前被守卫**误列为「现代语义整理」而豁免** —— 而它实际是
《易卦释义》**原典文言**，随 `to_dict()` 进入流年/流月/流日/流时四层爻断的
公开输出，却是唯一没有逐字回查保护的爻级字段。

判定口径：**整串连续命中** 或 **分句全覆盖命中**（分句按句末标点切，
短于 8 字的碎句不单独要求）。

实测：**356/376 整串命中；分句口径 376/376 全覆盖**；另 8 条底本原缺
（坤六二/屯上六/需九二/师上六/小畜九三/小畜上九/履九二/涣上九）已逐条列名留档。

同时修正该守卫文件头对 `yi` 的错误声明，并**补上缺失的 `sys.path` 注入**
（此前该文件的 `test_engine_exposes_same_data` 只能靠别的测试先导入
`tongshu` 才不报错，单跑必红 —— 隐式依赖 = 测试隔离缺陷）。

### 4.2 三元推导守卫（`tests/heluo/test_heluo_sanyuan.py`）

`sanyuan` 此前**零守卫**（`grep "sanyuan" tests/` → 0 命中），而它决定寄宫对象，
寄宫一变则全链判词全变。

守卫以 `heluo_adapter.py:76-79` 自记的**原典回查链**为准
（1504 上 → 1564 中 → 1624 下 → 1684 上 → 1744 中 → 1804 下），另加：
180 年周期不变性、三个分界边界点、端到端（adapter 的 era 与 `sanyuan` 一致、
寄宫与 `resolve_middle_palace` 直调一致）、兜底标记（`era_source == "fallback"`）。

**变异验证**：锚点 1864→1865 → **17 failed**（抓住）；分界 `<60→<59`、`<120→<119`、
中/下元互换 → 均抓住。锚点 ±1 之所以能被抓，是因为守卫同时断「锚点年 + 相邻年」。

### 4.3 爻辞吉凶方向值守卫（`tests/heluo/test_heluo_yi_direction.py`）

`_judge_direction` 是**全链吉凶方向的唯一来源**，此前**没有任何守卫断言过
任何一条 yi_signal 的 direction 值**（`grep "signal.direction" tests/` → 0 命中）。
把「凶」从关键词表删掉，守卫全绿，而下游照单全收 → **吉凶整体翻转，零报警**。

守卫的期望值**从《周易》原典爻辞独立推导**（含吉→吉、含凶→凶、吝厉→凶、
否则中平），与引擎的「正负词计数 + 强负面词」统计口径**是两套独立实现**
—— 守卫不能与被测同源，否则等于没守。

另覆盖：方向取值合法性、confidence 区间与单调性、空文本 → `NO_EVIDENCE`、
正负关键词表非空且**无交集**（交集=歧义规则，永不生效）、强负面词必在负向表内、
强度（爻位）位置语义（五爻 HIGH / 上爻 MEDIUM / 初爻 LOW）。

**口径差异留档**：24 条含「吝」「厉」的爻辞，引擎判 `MIXED`、本守卫的《周易》口径
判 NEGATIVE —— 引擎的 MIXED 更贴近经义（吝、厉皆非「凶」断），**以引擎为准**，
守卫不作为不一致项，但已在 docstring 中显式说明。

### 4.4 证据层值守恒 + 丢弃清单双向断言 + 静默降级留痕

（`tests/heluo/test_heluo_evidence_values.py`）

* `HL_JIEHOU_GUA` 的 `value` 与 5 个 `attributes` 必须**逐项等于**
  `result.seasonal_hexagram`（此前只有 `issubset` 的子集断言，删一条证据都不红）；
* 七条证据的 `rule_id` 集合**恰好**相等（此前只断言 6 条，第 7 条漏网）；
* 丢弃清单**双向**断言：被丢的必须**恰好**是留档清单
  （`KNOWN_PRODUCED_NOT_LINKED = {HL_HEXAGRAM_STRUCTURE}`，
  镜像于 `diagnosis_rule_graph.py:82-93` 记的「已注册未产出」三条）；
* 注册表每条规则必须有领域映射（否则落 default，语义错配）；
* 五处静默降级必须留痕（`era_source` / `yuan_qi_error` / 判词层 error 字典 /
  `_KZ_ERRORS` 逐盘清零）。

### 4.5 公开 API 签名契约守卫（`tests/heluo/test_heluo_public_api_signature.py`）

**本轮我自己踩的坑**：`era_source` 插在 `era` 与 `birth_year` 之间，
破坏了位置参数调用 `calculate(bazi, gender, hour, era, 2013)` ——
`2013` 被当成 `era_source` → `birth_year` 变 None → **12 年流年卦序列全错**。

该破坏被既有守卫 `test_heluo_liunian_guji.py` 捕获，但那是运气。
现把「参数顺序」显式钉成契约：新增参数**只能追加到末尾**，
`calculate` / `sanyuan` / `resolve_middle_palace` / `HeluoAdapter.compute` /
`compute_from_chart` 全部覆盖，并加一条**实测**（位置参数传 birth_year，
流年必须从该年起算）。

## 5. 有意**不做**的事（及理由）

审计还报了下列项，本轮**有意不做**：

| 项 | 不做的理由 |
|---|---|
| 清理「定义了但无调用者」的公共函数（`number_to_trigram`、`primary_shu_ge`、`qishu_dayun` 等约 10 个） | 零调用 ≠ 无用：这些是**公开 API**，可能被外部消费；删除属破坏性变更，无用户授权不做。`compute_liushi`（流时）尤其不能删 —— 用户裁决「到流日为止」是**生产层剥离**，算法本体须保留 |
| 接线诊断链（evidence → assertion → guidance → interpretation → metrics） | 这六个模块在 src/ 内互不调用，且**依赖主仓** `tongshu.pipeline` 形状。接线是**跨仓工程**，属主仓责任域，本轮越界 |
| `temporal.py` / `hexagram_state.py` / `dayu.py` / `time_sequence.py` / `relationship/engine.py` 的废弃标记 | 前四个已有 `DeprecationWarning`；`relationship/engine.py` 已由 2026-10-22 裁定保留并钉死缺陷。补标记是低价值清理，且改动面大 |
| `kuozhan_duanyu.json` 的逐字回查守卫 | 该数据的原典切片归属尚未取证（`起例卷之上` 里是哪一段未核），**无据不建守卫** |
| `yi_signal` 的方向值守卫「强断言」含吝/厉的爻辞 | 两套口径差异是**合理**的（引擎 MIXED 更贴近经义），强行统一会篡改经义口径。改为留档 |

## 7. 方法论（本轮新增教训）

1. **审计报告不是圣旨** —— 3 条结论被实测推翻。子代理的结论必须**逐条回源码核实**，
   否则会把误判当缺陷去「修」。
2. **「两套口径不一致」要先问哪套对** —— 引擎判 `MIXED`、我的独立判定判 `NEGATIVE`，
   引擎的更贴近经义。守卫不能强推自己那套。
3. **改公开 API 签名必须想到位置参数** —— 加参数插在中间 = 静默破坏既有调用。
   这类事故要**钉成契约**，不能靠运气被既有案例捕获。
4. **惰性物化不是缺失** —— `days: []` 看着像丢了数据，实为按需现算。
   端到端体检的「空值路径」必须逐条判读，不能按数量下结论。
5. **「锚点偏移无影响」也要算清楚** —— 60 与 180 整除，使三元对档内偏移不敏感；
   守卫要断在**档位边界年**上才抓得住。
