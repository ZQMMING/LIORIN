## 4. ★ 本表的**可执行版本**（2026-10-24 落地）

上表此前只是**文档**；判词层的 `evidence` 是**平铺**的字符串列表，
下游要判断「某条判词属于哪个维度」只能**解析中文** ⇒ 维度视图落不了地。

现已落地为**代码**：

| 件 | 位置 | 作用 |
|---|---|---|
| 维度表 | `src/heluo_engine/engines/heluo/dimensions.py` | 本表的**可执行**版本：12 个 L1 领域 + **41 个** L2 子维度（含 L3 载体、L4 出处） |
| 带标签的证据 | `guajie.TaggedEvidence` | `evidence` **仍是 `list[str]`**（消费方无感），额外记录逐条维度 id |
| 输出视图 | `gj["by_dimension"]` | 按维度归组；`items` 只带 `index` 回指 `evidence`（不复制全文） |
| 覆盖率 | `gj["dimension_coverage"]` | 逐维度条数 + **未标注条数**（不静默） |

**维度口径**
- 判据证据 → 41 个 L2 子维度之一；
- **口径/过程留痕**（历法口径自检、计算跳过、流时已剥离…）→ `PROCESS`
  （**刻意与 12 域分开** —— 过程留痕不是「人生领域判据」）；
- 未标注 → `UNCLASSIFIED`，**条数显式报出**（守卫断言为 0）。

**当前实现状态**（实测 1975 命例）：58 条判据证据 **100% 归位、0 落空**，
命中 6 个 L1 领域 / 13 个 L2 子维度。

### 4.1 ★ 维度缺口的**最小有据接入**（2026-10-24）

「婚姻/子女/父母/手足/夭横」几格**原典就在判词库里**
（「免克绝子孙」「亲眷刑伤，婚嗣孤克」「或生子孙」「兄弟之忧」…），
却因「只按卦名归位、不断语归位」而从未进证据链。

现按**原句匹配**接入（`engines/heluo/liuqin_tagger.py`）：
- **不生成新断语、不改一个字**；关键词用**判词库实际用字**（不臆造同义词）；
- 命中的**原句连同条件前缀**（「岁运逢之…」「数卦不叶…」）一并留证 ——
  条件式断语脱离条件引用即失真；
- 命卦层（`gua_lines`）与流年/流月层同时接入（维度表 L2 是「领域」，不是「时间层」）。

**实测**：判词库 1376 条断语中 **79 条**含六亲/婚育意象
（配偶征象 47 / 子息 12 / 兄弟爻 10 / 父母爻 7 / 琴瑟不和 3）；
维度覆盖 13 → **15**（多盘 12–15），新增 MARRIAGE / CHILDREN / PARENTS / SIBLINGS 域。

### 4.2 ★ 平台 17 类**候选证据**（2026-10-24）

河洛侧**只给候选**，L1/L2 与 L5 的最终裁定属平台（`dimensions.EVENT_TYPES`
是平台本体的**只读镜像**；`EVENT_TYPES` 17 类 / 域分布 4-5-5-3 与平台一致）。

- 每条候选带：平台默认方向 + **河洛侧有据方向** + 证据条目 + 判据出处；
- **河洛侧方向判不出就 UNKNOWN**（不猜）：遇元气/遇化工 → 吉；数凶 → 凶；
  叶/不叶 → 吉/凶；**命中死断 → UNKNOWN**（原典为条件式立断，阴骘两支并陈，
  不得径取一支）；
- **不给 0–1 分数**（原典只给吉凶不给数值）⇒ 强度以「证据条数 + 判据出处」表达；
- **「无候选」逐条钉死并显式报出**（当前 7 类无候选，附各自理由）。

> ⚠ 平台 ontology 的 `direction` 是**默认方向**，原典方向随卦/爻/叶不叶/岁运变
> ⇒ 方向由河洛判词层另给，两者可能不同（不同即留痕，不强行对齐）。

⚠ **未命中的维度 ≠ 未实现**：多数维度（婚姻、子女、父母、手足、人际…）的判据
尚未接入判词层 —— 这是**引擎能力缺口**，不是维度视图的缺陷；
下游消费时应以 `dimension_coverage.per_dimension` 为准，**不要**假设 41 个维度都有数据。
