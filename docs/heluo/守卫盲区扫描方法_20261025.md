# 守卫盲区扫描方法（变异测试，2026-10-25）

> 目的：回答「**每次测试还有缺陷？能一次把全部缺陷跑出来吗？**」
> 结论：**不能跑出「全部」缺陷**（缺陷空间无限），但可以**系统性地挖到当前手段的极限**，
> 并把「哪些是真空盲区」一次性列清。本文就是这套方法。

## 一、为什么以前「每次还有新缺陷」

以前的做法是**按需发现**：看到一个问题就查一个、修一个。
⇒ 这是**抽样**，不是扫描 ⇒ 必然反复漏。

真正能收敛的做法是**主动注入缺陷**，看守卫能抓到几个：

* 注入的缺陷被守卫抓到 ⇒ 守卫**有效**；
* 注入的缺陷**存活**（测试仍全绿）⇒ **守卫盲区**。

这叫**变异测试**（mutation testing）。

## 二、仓内已有的做法（及其局限）

`tools/heluo/mutation_verify_*.py` 共 **11 个手工脚本**，每个只挑 2~6 条变异。

| 局限 | 说明 |
|---|---|
| **变异是人挑的** | 挑不到想不到的盲区（如「条件写反」「下界差一」） |
| **覆盖面窄** | 11 个脚本 × 4 条 ≈ 40 条，而自动生成可达 **1163 条** |
| **每个脚本一套流程** | 11 份重复的「注入→跑→还原→校验」代码 |

## 三、本轮新增：自动化扫描（`tools/heluo/mutation_sweep.py`）

### 3.1 自动生成变异（AST 级）

对每个源文件解析 AST，机械地产生四类变异：

| 算子 | 例 | 模拟的现实错误 |
|---|---|---|
| `literal` | `0 → 1`、`True → False`、字符串改一个字 | 阈值写错、常量写错、**原典引用抄错字** |
| `op` | `+ → -`、`< → <=`、`== → !=` | 边界差一、比较反了 |
| `drop not` | `not X` → `X` | 否定漏了 |
| `return→None` | `return X` → `return None` | **返回值被吞掉**（最危险的一类） |

⚠ **只变异可执行代码**：跳过注释与 docstring（注释里的字面量改动不改变行为，
必然「存活」⇒ 全是噪音）。

### 3.2 两级筛（快 → 准）

每条变异都跑全量测试要 ~5 秒 ⇒ 1163 条要 1.6 小时。
故分两级：

1. **快筛**：只跑「与被测模块相关的守卫文件」（≤3 个），超时 25 秒；
2. **慢速确认**：快筛放过的再跑全量（超时 120 秒）。

实测：`time_layer_judgment` 29 条变异由「~5 分钟」降到「~2 分钟」。

### 3.3 ★ 关键：区分「等价变异」与「真盲区」

**存活 ≠ 盲区**。本仓大量防御性代码（如 `return ("", "")` 兜底）被变异后
**行为完全不变** ⇒ 那是**等价变异**，不是缺陷。

故引入**行为快照**（`tools/heluo/behaviour_snapshot.py`）：
对 5 个固定盘（男/女、纯卦/杂卦、不同流月流日）产出确定性 JSON，
对比基线与变异后的快照：

* 快照**相同** ⇒ **等价变异**（不是盲区，不必修）；
* 快照**不同** ⇒ **★真盲区**：行为变了，却没有任何守卫发现。

### 3.4 工程约束（继承已有脚本的教训）

1. **绝不改测试文件** —— 只改被测源码。否则守卫自身被改坏，
   自验证失效（2026-10-25 实测踩过：prune 同时改了 tests/，
   守卫被改坏 ⇒ 工具以为全绿 ⇒ 静默破坏）。
2. **隔离字节码缓存** —— `PYTHONPYCACHEPREFIX` 指向临时目录，
   否则 `.pyc` 复用会让「还原后复跑」拿到旧字节码 ⇒ 假绿。
3. **还原必须校验哈希** —— 每条变异还原后校验内容哈希，确保真的回到初始字节。
4. **日志写文件** —— 管道会缓冲 stdout，进度看不见。

## 四、用法

```bash
# 扫单个模块
python tools/heluo/mutation_sweep.py --module time_layer_judgment

# 扫全部河洛模块（1163 条变异）
python tools/heluo/mutation_sweep.py --all

# 限量（默认 120）
python tools/heluo/mutation_sweep.py --all --limit 400
```

进度看 `mutation_sweep.log`（**不是** stdout，管道会缓冲）。

## 五、扫描结果（2026-10-25 实测）

### `time_layer_judgment`（本轮新写的模块）

| 指标 | 值 |
|---|---|
| 变异总数 | 29 |
| 被守卫抓住 | **18** |
| ★ 真盲区（行为变了却没人发现） | **0** |
| 等价变异（输出不变，非盲区） | 11 |
| 源码还原校验 | 通过 |

⇒ 该模块的守卫**有效**；11 条等价变异来自防御性兜底（`or ""` 之类），不是缺陷。

### 扫描发现的**真缺陷**

`_polarity_of()` 是**死代码**（我重构后零调用）——
它让变异扫描的盲区清单被噪音污染，也误导读者以为该函数在起作用。

⇒ 已删（其判据依据已迁入实际使用路径的 `detail` 文本），
并新增守卫 `tests/heluo/test_heluo_no_dead_code.py`：
包内模块级函数/类**不得零引用**。

⚠ 该守卫必须把**主仓 vendor 目录**算进引用范围 ——
本包许多函数是**跨仓公开 API**（如 `transparent_ten_gods` 主仓引用 14 次），
只看包内会被误判成死代码。
⚠ 也不能把守卫**自身**算进去（它的注释会提到被检查的名字 ⇒ 死代码被自己「洗白」）。

## 六、这套方法能回答什么、不能回答什么

**能回答**
* 哪些规则/判据**改动后没人察觉**（真盲区）—— 一次列全；
* 哪些守卫是**摆设**（改了也不变红）。

**不能回答**
* 「全部缺陷」—— 变异算子只覆盖四类错误模式，
  逻辑错误、并发错误、性能问题、**语义选错判据**（如「判据本身取错原典句」）
  都不在变异算子覆盖范围内；
* 原典层面的正确性 —— 那由「判据须附原典出处」的**具名守卫**负责
  （见 `test_heluo_orig_slices.py` 等），不是变异测试的职责。

⇒ 两者**互补**：变异测试找「守卫的洞」，具名守卫守「判据的据」。
