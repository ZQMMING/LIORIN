河洛引擎 —— 独立部署指南（2026-10-25）。

本包是**自包含**的独立 Python 包：源码 + 运行数据 + 原典切片 + 依据文档
全部在 ``heluo_engine/`` 一个文件夹内，按包定位（``importlib.resources``），
与安装位置 / 运行目录 / CWD **全部无关**。

本指南面向「把引擎部署到服务器、接进业务系统」的场景。

════════════════════════════════════════════════════════════════════
一、最快路径（服务器上三条命令）
════════════════════════════════════════════════════════════════════

::

    # 1) 构建 wheel（在本仓库根目录）
    pip install build && python -m build --wheel
    #    产物：dist/heluo_engine-1.0.0-py3-none-any.whl

    # 2) 安装到服务器
    pip install dist/heluo_engine-1.0.0-py3-none-any.whl

    # 3) 自检（确认包内资源齐备、可定位）
    heluo-engine doctor

``doctor`` 输出 ``"result": "PASS"`` 即部署成功。

════════════════════════════════════════════════════════════════════
二、Python 侧接入
════════════════════════════════════════════════════════════════════

最小用法::

    from heluo_engine import HeluoAdapter

    ad = HeluoAdapter()
    res = ad.compute((1983, 11, 3, 12), gender="male", target_date="2026-10-23")

    res.prenatal.hexagram_name    # 先天卦
    res.yuantang.yuantang         # 元堂
    res.postnatal.hexagram_name   # 后天卦
    res.target_date               # 流日取用日（公历原值）

**目标日**（``target_date``）
    流日卦的取用日。不传 ⇒ 按**今天（北京时间）**自动推算
    （避免服务器时区/夏令时造成「今天」漂移）。
    ⚠ adapter 会把公历日期换算为**节气月序 + 自节起的日序**再喂给日卦层
    （公历 10 月 ≠ 节气十月：十月 = 立冬月，11/7 起）。换算规则见
    ``canonical.resolve_jieqi_window``。

**解读层**（六模块）
    ``res.interpretation`` 内含 ``platform_signals`` / ``interpretation`` /
    ``guidance`` / ``diagnosis`` / ``metrics`` / ``hexagram_state`` /
    ``dimension_view`` / ``event_candidates`` / ``warnings``。
    任一子块失败**不阻塞**主链，原因写入 ``warnings``（不静默）。

**平台信号**（给主仓/平台侧消费）::

    from heluo_engine import build_platform_signals
    signals = build_platform_signals(res)

    ⚠ 平台侧归一化有两处**已知缺口**（不在河洛域，需平台 owner 裁定）：
      ① ``gua_yao_map`` 只映射乾/坤两卦 ⇒ 其余 62 卦落 UNKNOWN；
      ② 方向判定用**全等**匹配，而河洛 ``shi`` 是长文本 ⇒ 恒判 NEUTRAL。
      详见 ``docs/heluo/河洛回灌接线决策单_20261024.md`` §3。

**黄历注入**（可选，让流日卦带农历）::

    def huangli_provider(solar_date: str):
        return huangli_engine.get_day(date.fromisoformat(solar_date))

    res = ad.compute(..., huangli_provider=huangli_provider)

    不注入时走 ``lunar_python`` 兜底，标注 ``source="lunar_python"``。

三、命令行接入（不想写代码时）
════════════════════════════════════════════════════════════════════

::

    # 排盘（JSON 输出）
    heluo-engine compute --birth 1983-11-03 --time 12:00 --gender male         --target 2026-10-23

    # 只要关键字段
    heluo-engine compute --birth 1983-11-03 --time 12:00 --brief

    # 解读层
    heluo-engine interpret --birth 1983-11-03 --time 12:00 --target 2026-10-23

    # 查判词
    heluo-engine gua --name 观 --yao 初六

    # 自检 / 版本 / 安装位置
    heluo-engine doctor
    heluo-engine --version
    heluo-engine --where

退出码：0 = 成功，1 = 参数或运行错误（便于 shell 判成败）。

════════════════════════════════════════════════════════════════════
四、依赖与运行环境
════════════════════════════════════════════════════════════════════

Python ≥ 3.11。运行依赖（``pyproject`` 已声明，装 wheel 时自动带上）：

============ ==========================================================
sxtwl        干支/节气历算（**必需**；缺则节气相关层不可用）
lunar_python 农历兜底（流日黄历无注入时用）
chinese-calendar / pyyaml / jsonschema / pydantic  辅助
tzdata       Windows 时区数据（Linux 免装）
============ ==========================================================

⚠ **sxtwl 是硬依赖**：节气窗口、节气月序、真太阳时都基于它。
  缺失时引擎**不会崩**，但相关层会显式留痕（如 ``target_date_note``
  写明「节气表不可用，流日层退回公历月日口径」）——
  **缺失被当成正常，比答错更坏**，故留痕是刻意设计。

════════════════════════════════════════════════════════════════════
五之二、⚠ 必须在**干净目录**里运行（实测踩过的坑，务必读）
════════════════════════════════════════════════════════════════════

Python 会把**当前工作目录**放进 ``sys.path[0]``。因此：

* 若 CWD 里有 ``inspect.py`` / ``json.py`` / ``types.py`` 这类
  **与标准库同名**的 ``.py``，它会**替换**标准库模块；
* 后果举例（本项目 2026-10-25 实测）：CWD 里有个一次性审计脚本
  ``inspect.py`` ⇒ ``dataclasses`` 在 import 期抛
  ``AttributeError: module 'inspect' has no attribute 'get_annotations'``
  ⇒ 引擎 import 失败；**而且**那个 shadow 文件被执行，向 stdout 打印了
  800 多条无关内容，把真正的错误**彻底淹没**。

**处置**

1. 在**专用空目录**里运行引擎（不要用系统 TEMP，那里常积着历史脚本）；
2. 部署后先跑 ``heluo-engine doctor`` —— 它会显式检查
   「CWD 有无标准库同名 .py」，发现即 ``FAIL`` 并列出文件；
3. 自检脚本 ``tools/heluo/build_and_verify.py`` 已内建该检查
   （并用新建的空目录做 CWD），跑 ``--venv`` 即可复现一次完整部署验收。

════════════════════════════════════════════════════════════════════
五、与主仓共存（不装成外部依赖的方案）
════════════════════════════════════════════════════════════════════

若不想让服务器装外部包，可把 ``src/heluo_engine/`` **整目录**拷进主仓
（与 ``src/tongshu/`` 平级），主仓 ``[tool.setuptools.packages.find]
where=["src"]`` 会**自动**纳入打包，源码**零改写**。

⚠ 两副本并存会漂移 ⇒ 用同步工具：
  独立包 ``tools/heluo/sync_to_main_repo.py``（镜像同步，含删除多余文件）。
  比较时**归一化换行符与 BOM** —— 否则 Windows checkout 的 CRLF 与
  独立包的 LF 会被逐字节比较误报成几十个「内容不同」。
