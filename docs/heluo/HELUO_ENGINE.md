## 1. 引擎是什么

按《河洛真数》原典做的**离线推演引擎**，接排盘输入（出生公历日期/时辰/性别）→ 算出本命卦 / 元堂 / 后天卦 / 大运 / 流年 / 流月 / 流日 / 节候 / 化工 / 解卦 / 诊断 / 建议。

本分支**只包含河洛域**（`src/tongshu/engines/heluo/`）的代码、守卫、原典数据与文档。**不包含显示层、pipeline、render、其它引擎**。

## 2. 计算管线（calculation pipeline）

```
出生公历 → 真四柱（BaziAdapter 真太阳时校正）
  → HeluoCanonical.calculate(bazi, gender, birth_hour, birth_year, birth_date, target_year=...)
       ├─ 天数地数（compute_tian_di_shu）
       ├─ 先天卦（determine_prenatal_hexagram）
       ├─ 六爻（build_six_lines）
       ├─ 后天卦（compute_postnatal）
       ├─ 时间序列（_build_timeline(target_year=...)）── fast-path
       ├─ 卦象结构（analyze_hexagram）
       └─ 节候卦 + 化工（_compute_seasonal_hexagram / _compute_huagong）

  → HeluoResult = { input, numbers, prenatal, yuantang, postnatal, timeline,
                     structure, hua_gong, era, seasonal_hexagram, guajie }

  → YiAdapter.adapt() → YiStructure          （跨模块，本分支不包含）
  → YiInterpretationEngine.interpret() → YiInterpretation  （跨模块，本分支不包含）
  → H8 解卦层（build_guajie_from_result）── 50 条 evidence  （河洛内）
```

## 3. 时间口径（用户口径「时间上接黄历引擎」）

```
应期日 → 优先取 HuangliDay.lunar_month / lunar_day（黄历权威值）
        ↓ 不可用
        回退 lunar_python
        ↓ 不可用
        回退 公历口径
```

`_heluo_lunar_target(target_date, huangli_day=None)` 在 `compute_stage.py` 定义（compute_stage 是河洛接线边界，可动）。`_huangli_for_heluo(day)` 取黄历对象，失败返回 None。

### 12.2 流日层口径（一卦管 6 日、一爻一日）

定稿原文：
> 「完整起卦：只做1次，生成流日本卦本体（本卦、互错综、基础卦气全部一次算好）
> 　之后6日唔再起完整卦；每日只取对应爻（初爻→第1日，二爻→第2日……上爻→第6日），
> 　单独跑该爻嘅爻变、卦气、象义运算，属于轻量爻运算。
> 　6日用完，先至起下一个新流日卦。」

落码（`timeline_yun.compute_daily_base_hex`）：

- **日序固定 6 日一组**：每月 5 卦 × 6 日 = 30 日（K3-447 L1154
  「日卦者每月變五卦每卦管六日方成一月五六三」+ K3-448 L475/L483
  「一日共管六日也」）
  · 硬算例（K3-448 L482-483）：七月「初二日午时」立秋起，第一卦管初二~初七，
    「至十四日」第三卦起 —— 初二 + 12 = 十四，**日序恒 6 日一组**，铁证
- **时刻按实际节气间隔均匀推移**（K3-448 L491「以此推之则每日添一刻七分天 六日」）：
  第 k 段起时刻 = T0 + k*(T1-T0)/5；节气非 30 日时每日多/少推一点，
  整月从节到节对齐
  · 实测：某年 7 月 jie_span_days = 31.12 日 → 第 3 段起时刻 `2026-08-20 06:29`
  · 这才是「不可执定『卦六日』死板规则」的含义：**六日仍是六日，
    但六日所跨的时刻随实际节气间隔变**
- 每段 1 个流日本卦（本体/互/错/综/卦气**一次算好**）；互错综复用 `hexagram.py`
  的权威实现，不自造第二套口径
- 段内 6 日共用本卦，每日只取对应爻位（**首日从初爻开始**：初→1日 … 上→6日）
  做**轻量爻运算**（爻变 + 卦名 + 卦气五行），不再起完整卦
- 段间链式推进：第 k 段本卦 = 链式 `day_lines[k*6]`
- 本任务只算**目标日所在的那一段**
- `daily_yao` 每条含 `day_no / day_in_seg / active_yao / yao_index / yao_nature /
  changed_name / changed_upper / changed_lower / changed_lines / changed_element`

### 12.3 与原典 L129 的关系（如实留档）

原典《河洛真数·起例卷之上》L129 另一套口径：

### 14.1 唯一一个「已到判词层」的缺陷：流日双口径

  日段自带 `rule` 标记），形状嗅探仅作旧 payload 兜底；

  「两条路径必须给出同一卦名/动爻/判词」。

### 14.16 出生年占位导致流年/流月/流日整条链错位（跑案例时撞出）

**来源**：2026-10-22 跑原典算例做对拍时发现「同一盘、同一 target，判词却随
一个可选参数变」，追出来的第二个真缺陷。

**缺陷**：`canonical.calculate` 原先**不解析出生公历年** —— `birth_year=None`
一路传到 `_build_timeline`，在那里被**硬编码成 1984（甲子年）**作占位。

1984 与真实出生年**不同余 60**（除非出生年恰是 1984/1924/2044…），于是
`compute_liunian` 的 `year = birth_year + age - 1` 算出的流年干支**整体错位一年**
→ 流年卦 → 流月卦 → 流日卦**整条链**的判词都错，而**全程无任何报错或留痕**。

**实测（修复前，同一盘 癸亥 甲寅 丁巳 戊午 / 1983-11-03 午时 男）**：

| 传参 | 流年卦 | 流日本卦 | 流日卦 |
|---|---|---|---|
| `birth_year=1983` | 泽火革 | 地水师 | 升 九三 |
| 不传 `birth_year`（只给 birth_date） | 乾为天 | 山地剥 | **艮** 九三 |

同一出生数据，因一个可选参数传不传而**判词不同**。

**修法**：

1. `birth_year` 未提供但 **birth_date 有效** → **取 birth_date 的公历年**
   （精确、无 60 年歧义；这是主流用法，birth_date 本就带着年份）。
2. 两者皆无 → **保留 1984 占位**（维持既有流年区间与既有行为不变），
   但由 `HeluoResult.birth_year_source="placeholder"` 标记，
   `guajie` 在 evidence 里**明确留痕**：「出生年：占位推流年……流年干支与
   真实出生年可能错位……」。*缺失输入被当成真实输入，比答错更坏*。
3. `_build_timeline` 里那处占位改为**显式报错**，不再静默给错答案。
4. 附带新增 `canonical._birth_year_from_ganzhi`（年柱干支 → 出生年，60 甲子
   近似；干支 60 年一循环，故取解集任一年皆得同一串流年干支）——
   本轮**未**启用为默认路径（会让流年区间移动、改变既有行为），保留为工具并有守卫。

守卫：`tests/heluo/test_heluo_birth_year_resolution.py`（9 条）—— 传不传
`birth_year` 判词必须逐字一致、不得回落到 1984 占位时的流年卦、占位时
必须在 evidence 留痕、给了 birth_year/birth_date 时不得出现占位痕、
占位时流年区间仍覆盖 2026、60 甲子反推全覆盖。

### 14.21 起月卦「双月取应爻」的**应爻基准**裁定（跨书互证，2026-10-22）

《河洛真数》起例卷之上 L124-L126 只给了一句规则：

> L124「凡起月卦，就年卦中前一位起，**单月变爻，双月变应爻**。
> 假如观卦上九爻流年，进一位从初爻变起。」
> L126「又假如**小象是泰卦九二**，卦**应爻居五**，双月取应爻。」

「双月变应爻」的**应爻以什么为基准**，字面有两种读法，二者恰好差一个爻位：

| 读法 | 基准 | 后果 |
|---|---|---|
| A 以**元堂**（年卦流年爻）为基准 | 元堂 + 3 | 六个双月**同变一爻** |
| B 以**当月阳月的居位变爻**为基准 | 居位 + 3 | 六个双月**逐月递变**，覆盖全部六爻 |

**《河洛理数》卷五「月卦」给出四组显式逐月对拍，直接判 B**：

> 「如前五月是**小畜三爻**，六月则取**小畜应爻上九**」
> 「如前七月是**乾九四**，八月则取**乾卦应爻初九**」
> 「九月……**大有六五**……取**大有应爻**……**离卦六二**」
> 「如前十一月是**大壮上爻**，则十二月取**大壮应爻**……**归妹六三**」

（底本：`D:\顺天系统资料\河洛理数_OCR\修正版\河洛理数_1632笔写本_K3-448_修正版.txt`
L469-L471；`…\河洛理数_1871增补本_K3-447_修正版.txt` L1132-L1146。）

四组一律是「双月 = 该阳月**居位变爻**的隔三位应爻」（三爻→上爻、四爻→初爻、
五爻→二爻、上爻→三爻），且该链**阳月居位序 = 上爻 → 初、二、三、四、五、上**，
正是「元堂 + 1…+6」。读法 A 会让六个双月同变一爻，与这四组实证**直接冲突**。

**同书互证**：《河洛真数》起时卦例与起月卦例同段，且明言「**日卦变时卦，与年卦变月卦同**」：

> L402「凡居位进一爻起，**子时其应爻**则丑时也。……取**变卦应爻**变之。」

「其应爻」= **刚变之爻**的隔三位（时卦例），与读法 B 同基准。

**L126 泰例如何落位**：泰卦元堂在九二 → 阳月居位序 = 三、四、五、上、初、**二**
→ 走到居位九二的是**十一月**，其后的**十二月双月**取九二的应爻 = 1+3 = **4（五爻）**，
与原典「**卦应爻居五，双月取应爻**」逐字吻合 ✓（读法 A 虽也给出五爻，但会让
其余五个月双月同变五爻，与上引四组实证冲突，故不取）。

**落码**：引擎口径不变（`timeline_yun.compute_liuyue`，`ying = (flip_idx + 3) % 6`），
即读法 B；docstring 已补记该裁定与引文出处。新增守卫
`tests/heluo/test_heluo_original_cases.py::TestCase12HeLuoLiShuYueGua`

### 14.26 流时卦：**生产层维持剥离**（用户裁决：到流日为止），算法本体按前法更正（2026-10-22）

《河洛真数》起例卷之上 L402「起时卦例」给出**两法**并明言「**二法皆通，前法为优**」：

* **前法**：「凡起时卦，于日中寻时，就值日卦上从前一爻起，子丑寅卯辰巳六时，主进数
  变去；值日卦后一爻起，午未申酉戌亥六时，主退数变去。假如得乾卦初爻值日，则从二爻
  变起。」→ 子…巳 进数（+1…+6）、午…亥 退数（-1…-6），**十二时皆变爻**。
* **后法**（又云）：「日卦变时卦，与年卦变月卦同。但子寅辰午申戌居左，变爻用点，
  丑卯巳未酉亥居右取应，变爻不同点。」→ 阳时链式变爻、阴时取应。

#### 14.26.1 案例验证发现：引擎原实现**既非前法，也非后法**

原 `compute_liushi` 把两法**混用**：前六时用后法的阴阳时分配（变爻 1,4,2,5,3,0），
后六时用「退数 + 阴时取应」的第三种组合（5,2,4,1,3,0）。以原典实例
（乾初爻值日）逐时对拍：

| 时 | 原实现 | 前法 | 后法 | 原=前 | 原=后 |
|---|---|---|---|---|---|
| 子 | 天火同人 | 天火同人 | 天火同人 | ✓ | ✓ |
| 丑 | 离为火 | 天雷无妄 | 离为火 | ✗ | ✓ |
| 寅 | 天雷无妄 | 风雷益 | 天雷无妄 | ✗ | ✓ |
| 卯 | 泽雷随 | 山雷颐 | 泽雷随 | ✗ | ✓ |

##### 14.35.1.1 死断取爻的原典核实（2026-10-24 逐字复核）

**死断原句**（起例卷之下·后天详说 L1555，四库全书本一致）：

> 「若行后天，连三爻不吉，必多坎壈。若过了第四爻，遇凶，十死八九。

**取爻的真正依据**（起例卷之上 L369，**三源逐字一致**：

**这是原典自注**：「流年」在原典里被直接定义为「小象行年爻」。

* L783「**流年爻辞**吉凶有未交生，虚当岁数，即见祸福者……」（流年判到爻辞层）；
* L486「如遇**本身卦爻理体**不吉，便可以死断之，其理然也」（死断的爻层判据）。

旧实现把大运卦的爻位号套到流年卦上取爻 —— 原典无此配法。

### 14.37 真太阳时边界与死断触发率（2026-10-24 核实）

#### 14.37.1 真太阳时：**河洛域内无需改动**，但入口分两种

⚠ 先纠正本引擎此前的一处**自我表述错误**：§2 计算管线图写
「出生公历 → 真四柱（BaziAdapter 真太阳时校正）」，
容易被读成「河洛入口自己会做真太阳时校正」。**并非如此** —— 校正发生在
**上游 TimeResolver**，且**只发生在正式链路**上。逐环节实测如下。

| 环节 | 实际用的时间 | 依据 |
|---|---|---|
| `TimeResolver.resolve_context()` | ✅ **真太阳时** | 中山实测：民用 1983-11-03 11:00 → 真太阳时 **10:49:50**（经度差 −26.48 分 + 均时差 +16.32 分 = **−10.16 分**） |
| `BaziEngine.compute()` **独立入口** | ❌ **民用时间** | `solar_date[3]` 直接喂 sxtwl；引擎自身不做 longitude/EoT 校正（其 docstring 明写「全部由上游 TimeResolver 完成」） |
| `BaziAdapter.compute(ctx)` 正式链路 | ✅ 真太阳时（时柱/日柱） | `ctx.bazi_view` = `(effective_date, effective_hour)`，而 `effective_hour` 已是真太阳时换算后的时辰；`birth_civil_datetime` 只用于**节气边界判断**（节气是钟表定义，用民用时间正确） |
| 河洛 `HeluoInput.true_solar_datetime` | ⚠ **只落记录，不参与任何判定** | `canonical.py` 默认值就是 `birth_date + "T00:00:00"`，形同虚设 |

**为什么河洛域内不需要「接线」**：河洛的先天卦/后天卦/元堂吃的是**时柱地支**
（`birth_hour`），而时柱由八字给出 ⇒ 真太阳时的影响是**通过时柱间接传导**的，
河洛无须自己再算一遍。

**实测影响（同一出生时刻 1983-11-03 北京 11:00，中山）**：

| 路径 | 时柱 | 先天卦 | 后天卦 | 元堂 |
|---|---|---|---|---|
| 独立入口（民用时间） | **午** | 风山渐 | 火风鼎 | 初六 |
| 正式链路（真太阳时） | **巳** | **地山谦** | **火地晋** | 初六 |

⇒ 真太阳时差 10 分钟，**跨越了午/巳时辰界** ⇒ 先天卦与后天卦**完全不同**
（整盘判词的基础就变了），而元堂恰好相同（初六）。

**边界结论**：
* 走**正式链路**（平台主链 `compute_from_context`）→ 八字已用真太阳时
  ⇒ 河洛自动吃到 ⇒ **河洛域内零改动**；
* 走**独立入口**（`HeluoAdapter.compute()`，本包测试与单用例在用）
  ⇒ 用**民用时间** ⇒ 这是**八字独立入口**的边界，**不在河洛域**；

#### 14.37.2 死断触发率实测（1392 盘大范围扫盘）
