# 64 卦 → 平台 17 类事件本体：原典候选对应表（2026-10-24）

> **性质**：**平台侧映射提案**，不是河洛域判据。
> 平台本体定义（权威）：主仓 `src/tongshu/spec/event_ontology_v1.py`
> —— 4 域 / 17 类 / 5 方向 / 3 粒度，单父域约束。
> 原典**没有**这套切分。河洛能提供的是「**原典说了什么**」；
> 「哪一卦算哪一类事件」必须由平台 owner 裁定并回写为平台侧规则表。


## 0. 先看清三条约束（不看清必然做错）

**① 方向必须留在河洛侧。** 平台 ontology 给每个 event type 写死了 direction
（`MARRIAGE`=POSITIVE、`DIVORCE`=NEGATIVE、`HEALTH_ISSUE`=NEGATIVE…），
但原典判词的方向随**卦/爻/叶不叶/岁运**变 —— 同一个「婚」字既可能断吉也可能断凶。
⇒ 映射只能是「**卦/爻 → 事件类型**」，**不带方向**；方向由判词层给。
若平台照搬 ontology 的固定方向，河洛侧会输出方向相反的信号。

**② 关键词命中 ≠ 主判此事件。** 同一卦常同时命中 1–8 类。
下表的证据只说明「该卦原典**谈到**这件事」，不说明它**主判**此事。

**③ 原典不支持这个切分。** 17 类里：3 类无对应、1 类无区分度、3 类只有极弱支撑。详见 §1、§3。

   ⇒ 这三类**不能**由河洛提供映射，只能由平台侧另行定义或合并。
2. `DEGREE` 命中 60/64 卦（语汇「功名」106 次）—— 几乎每卦都谈，
   **判别力≈0**，不能作映射依据；它其实覆盖了 `EXAM`+`ADMISSION`+`DEGREE` 三类的语义。
3. `LEGAL_ISSUE`（讼 87 / 争讼 19 / 狱 30）与 `HEALTH_ISSUE`（有疾 17 / 疾病 7）是
