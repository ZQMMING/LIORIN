# 子平八字引擎架构文档

> 版本：v1.0 | 日期：2026-09-21 | 基线：79.0%单一对齐率 + 98.2%命中率@K

## 一、架构总览

### 1.1 设计原则

| 原则 | 说明 |
|------|------|
| 布尔+多态枚举 | 不使用评分/权重/阈值，所有判断基于布尔条件和枚举值 |
| 多维拓扑网络 | 五行力量通过网络拓扑传播，不做单一数值压缩 |
| 多轨并行 | 用神四轨（格局/调候/病药/体用）并行输出，冲突保留不裁决 |
| 原著优先 | 所有规则以六部经典原文为准，争议先取证再裁决 |
| 旺衰≠强弱 | 月令维度（wang_shuai）与根气+党众维度（qiang_ruo）独立输出 |

### 1.2 三层架构

```
┌─────────────────────────────────────────────────────────┐
│                    应用层（Application）                   │
│  dayun_align.py（对齐脚本）| 前端展示 | 用户查询          │
├─────────────────────────────────────────────────────────┤
│                    领域层（Domain）                        │
│  用神引擎 | 大运喜忌 | 应期力量 | 冲突保留 | 分看输出    │
├─────────────────────────────────────────────────────────┤
│                    事实层（Facts）                         │
│  排盘 | 透藏 | 根类 | 旺相 | 力量结构 | 力量网络 | 气候  │
└─────────────────────────────────────────────────────────┘
```

## 二、核心模块链路

### 2.1 完整执行链路

```
输入：四柱（年月日时）
    ↓
[L0] l0_fact_builder.build()
    → 基础事实：天干地支、藏干、十神、组合事实
    ↓
[L1] 日主结构层（并行）
    ├─ power_structure.build_power_structure()  → 力量结构
    ├─ root_class.build_root_classes()           → 根类（重根/轻根/无根）
    ├─ tou_cang.build_tou_cang()                → 透藏关系
    ├─ wang_xiang.build_wang_xiang()            → 旺相休囚
    ├─ root_relations.build_root_relations()    → 根支关系
    ├─ two_side.build_two_side()                → 两端构成
    ├─ branch_tier.build_branch_tiers()         → 地支层级
    └─ tian_he.build_tian_he()                  → 天干五合
    ↓
[L2] 力量层
    ├─ wuxing_power.build_wuxing_power()        → 五行力量（布尔+枚举）
    ├─ power_network.build_power_network()       → 力量网络（拓扑传播）
    ├─ build_spectrum_topology()                 → 谱拓扑
    └─ build_spectrum_from_power()               → wang_shuai（月令）+ qiang_ruo（根气+党众）
    ↓
[L3] 格局与气候层
    ├─ climate_candidates.build_climate_candidates() → 调候候选（QTBJ）
    ├─ climate_structure.build_climate_structure()   → 气候结构（寒暖燥湿）
    └─ special_pattern.build_special_patterns()       → 特殊格局（从格/专旺/化气）
    ↓
[L4] 用神引擎
    └─ yongshen_engine.build_yongshen_engine()
        → 四轨并行：格局轨(PZZQ) / 调候轨(QTBJ) / 病药轨(SFTK) / 体用轨
        → 输出：primary（主用神）、secondary（次用神）、avoid（忌神）
        → 输出：yongshen_paths（激活轨道）、spectrum_tier（tier2档位）
    ↓
[L5] 应期层
    ├─ transit_power.build_transit_power()      → 大运/流年力量重算
    ├─ transit_clash_verdicts()                 → 冲支结果三态（衰者拔/旺者发/两停）
    └─ dayun_xiji.build_dayun_xiji()            → 大运喜忌（互动检测+冲突保留+分看）
    ↓
输出：完整命局分析 + 大运喜忌 + 流年趋势
```

## 三、用神四轨架构

### 3.1 四轨定义

| 轨道 | 理论来源 | 激活条件 | 输出 |
|------|----------|----------|------|
| 格局轨 | 子平真诠(PZZQ) | 正格/从格/专旺格 | 格神用神 |
| 调候轨 | 穷通宝鉴(QTBJ) | 冬夏生人（亥子丑/巳午未月） | 调候用神 |
| 病药轨 | 神峰通考(SFTK) | 命局有病（五行偏枯） | 药神 |
| 体用轨 | 滴天髓(DTS) | 扶抑（身旺/身弱） | 扶抑用神 |

### 3.2 轨道优先级（来自原著）

| 条件 | 优先级 | 依据 |
|------|--------|------|
| 生于亥子丑或巳午未月 | 调候轨优先 | 《穷通宝鉴》"调候为急" |
| 生于其他月份 | 格局轨优先 | 《子平真诠》"专求月令" |
| 格局破 | 病药轨优先 | 《神峰通考》"有病方为贵" |
| 从格/专旺格 | 体用轨优先 | 《滴天髓》"从象" |

### 3.3 冲突保留原则

四轨输出可能冲突（如调候轨判忌、格局轨判喜）。引擎不强行裁决，而是：
1. 输出所有激活轨道的候选
2. 标注冲突类型
3. 由下游消费层（如dayun_align）按优先级规则选择主判断
4. 互动检测作为辅助提示，不参与主判断

## 四、旺衰≠强弱架构

### 4.1 两个独立维度

| 维度 | 模块 | 判定依据 | 输出 |
|------|------|----------|------|
| 旺衰（wang_shuai） | spectrum_from_power | 月令维度（得令/失令） | 得令/失令 |
| 强弱（qiang_ruo） | root_class + two_side | 根气+党众维度 | 强/弱（含有效性过滤） |

### 4.2 tier2档位映射（5档）

| wang_shuai | qiang_ruo | tier2 | 原著依据 |
|------------|-----------|-------|----------|
| 得令 | 强（重根+党众） | 从强/专旺 | 《子平真诠》"得时为旺，党众为强" |
| 得令 | 弱（有根） | 旺 | 普通旺 |
| 得令 | 弱（水旺木浮） | 衰 | 《滴天髓》"水泛木浮" |
| 得令 | 无根 | 中和 | 《子平真诠》"得时不旺" |
| 失令 | 强（重根+党众） | 中和 | 《子平真诠》"虽失时而不弱" |
| 失令 | 弱（轻根） | 衰 | 普通衰 |
| 失令 | 无根 | 从弱/从格 | 衰极/太衰 |

### 4.3 有效性过滤层

qiang_ruo的原始判定（有根+有帮扶→强）之后，增加有效性过滤：

| 条件 | 效果 | 原著依据 |
|------|------|----------|
| C寒湿过重 | 印不能生 → 帮扶失效 | 《穷通宝鉴》冬月火弱 |
| B根被冲 | 根被冲拔 → 根失效 | 冲支结果三态 |
| 水旺木浮 | 根被水漂浮 → 根虚浮 | 《神峰通考》水泛木浮 |

输出格式：
```json
{
  "qiang_ruo": {
    "raw": "强",
    "effective": "弱",
    "failure_reasons": ["水旺木浮"],
    "evidence_grade": "INFERRED"
  }
}
```

## 五、三个架构里程碑

### 5.1 V7.18：冲突保留输出架构

**问题**：元素级判断与互动级判断冲突时，强行裁决会导致误判。

**方案**：元素级与互动级并行输出，冲突时不裁决，标注"不确定"。

输出结构：
```json
{
  "element_judgment": {"result": "喜/忌/中性", "in_fav": bool, "in_avoid": bool},
  "interaction_judgment": {"has_interaction": bool, "types": [...], "may_xi": bool, "may_ji": bool},
  "conflict": {"has_conflict": bool, "type": "元素级喜 vs 互动级可能忌", "resolution": "保留多解不裁决"}
}
```

**生产链路集成**：dayun_align.py消费dayun_xiji的互动检测作为辅助层，主判断仍用dayun_align（79.0%基线不变）。

### 5.2 V7.19：分看输出结构

**问题**：十年大运整体判断丢失阶段差异。

**方案**：输出first_5（前5年）+ last_5（后5年）+ overall（整体）三个字段。

输出结构：
```json
{
  "first_5": {"gan": "庚", "gan_wx": "金", "result": "喜"},
  "last_5": {"zhi": "午", "zhi_wx": "火", "result": "中性"},
  "overall": {"result": "喜", "mode": "YUANHAI_FENKAN"}
}
```

### 5.3 V7.20：分看判断逻辑

**问题**：分看输出结构有了，但判断逻辑未分看。

**方案**：移植V7.20分看逻辑到dayun_align：
- 前期（first_5）：天干主导，地支辅助
- 后期（last_5）：地支独立，弃天干（渊海模式）

判断逻辑：
```
前期：
  IF 天干喜且不忌 → 喜
  ELIF 天干忌且不喜 → 忌
  ELIF 地支喜且不忌 → 喜
  ELIF 地支忌且不喜 → 忌
  ELSE → 中性

后期：
  IF 地支喜且不忌 → 喜
  ELIF 地支忌且不喜 → 忌
  ELSE → 中性
```

**多模式备用**：
- 模式A（渊海子平）：前5天干，后5地支 ✅ 当前实现
- 模式B（三命通会）：前5干支，后5弃干
- 模式C（滴天髓）：十年整体，盖头截脚修正

## 七、关键设计决策

### 7.1 为什么不用评分加权

**问题**：ratio = self_score / (self_score + opp_score) 把所有维度压缩成一个数字，然后映射到七档。

**风险**：
1. 参数（W_BENQI=6.0, T_WANG=0.45等）都是案例拟合，无原著依据
2. 换案例就全部报废（过拟合）
3. 无法解释每个判断的原因（黑盒）

**方案**：布尔+多态枚举+多维拓扑网络。每个判断都有明确的布尔条件和原著依据。

### 7.2 为什么互动级判断不强行裁决

**证据**：V6.0–V6.6七轮互动级试错全部回退。

**原因**：互动级判断（冲/合/泄）的后果依赖多个维度的组合，单一布尔条件无法覆盖。

**方案**：冲突保留输出。元素级与互动级并行输出，冲突时标注"不确定"，不强行裁决。

### 7.3 为什么dayun_xiji不切换为主判断

**验证结果**：
- dayun_align对齐率：79.0%（281例）
- dayun_xiji对齐率：71.1%（45例样本）

**原因**：dayun_xiji的十神级/藏干/盖头截脚等细致判断引入了误判，倾向于判忌（8/13不一致是"dx判忌但原典判吉"）。

**方案**：混合方案。dayun_align保留主判断（79.0%），dayun_xiji的互动检测作为辅助层（提示器），不参与主判断。

## 九、长期规划

### 9.1 十干级精度（长期）

**当前状态**：五行级判断（壬癸不分、庚辛不分）。

**目标**：全轨道十干级升级（不只调候）。

**风险**：之前原型44.0%失败，需要根本性重新设计。

### 9.2 四轨并行重试（长期）

**当前状态**：用神引擎已合并四轨，分开反而降低精度（V1–V3失败：57.7%/55.3%/58.2%）。

**目标**：数据源统一后重试。

**风险**：需要重新设计，不是简单重试。

### 9.3 前端展示设计（中期）

**核心问题**：多解输出如何呈现给用户？

| 输出类型 | 展示方式 |
|----------|----------|
| 单一结论 | 直接展示 |
| 冲突保留（多解） | 并列展示+来源标注 |
| 分看输出 | 前5/后5分别展示 |
| 互动检测 | 作为提示标注 |
