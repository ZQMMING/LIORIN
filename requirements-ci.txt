# 河洛引擎 CI 依赖锁定（2026-10-26）
#
# ⚠ 为什么需要这份文件
#   pyproject.toml 里依赖写的是**下限**（``sxtwl>=2.0.0``）⇒
#   CI 每次都装**当时最新**的版本 ⇒
#     · 上游一发布新版就把 CI 打红，而**与本次改动无关**（不可复现的失败）；
#     · 昨天的绿与今天的红可能只是依赖漂移 ⇒ 红灯噪音掩盖真问题。
#   ⇒ 这份文件锁定**已验证过的**版本组合 ⇒ CI 结果可复现。
#
# ⚠ 怎么用
#   CI 里：``pip install -e ".[dev]" -c requirements-ci.txt``
#   ⚠ **不**锁死 pytest/mypy/ruff 的**补丁号**以外的东西 ——
#     本文件锁的是**全量版本**（含传递依赖的关键项）⇒
#     同一提交在任何时间装出来的环境都一样。
#
# ⚠ 什么时候要更新
#   升级依赖时：先本地 ``pip install -U <包>`` ⇒ 跑全量测试 ⇒ 更新本文件。
#   ⚠ **不要**只改本文件不改 pyproject.toml（两边必须兼容：
#     pyproject 的下限 ≤ 本文件的锁定版本）。
#
# ⚠ 与本文件冲突时以谁为准
#   **pyproject.toml 是声明**（依赖关系与下限）；
#   **本文件是锁定**（本次 CI 实际安装的具体版本）。
#   pip 会同时读取两者：若本文件的版本不满足 pyproject 的下限 ⇒ 安装失败
#   ⇒ 这正是我们要的（不一致时立刻暴露，而不是装出一个半新半旧的环境）。
